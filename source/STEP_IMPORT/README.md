# STEP_IMPORT（内部 C++20）

显式通用装配入口支持固定 AP214 范围内独立的 `WireframeModel` 定义。每个定义拥有
本地毫米坐标下的曲线／点，实例共享只读定义及独立变换；`BodyCount` 为零，通过
`AssemblySnapshot::WireframeModel` 取得 owning 快照。源实体、单位、参数及全部 GCS
成员保留，不推断连接或材料角色；整份装配成功后才发布。

快照提供 owning `WireframeView`、源与单位信息和 native part 存档，清空 outcome／报告后
仍可查询。裁剪 B 样条保留 trim_1／trim_2 原 lexeme 和方向；实际 native 自然域须匹配
源参数的 binary64 转换，拒绝吸附、静默改域或归一化为 [0,1]。当前接纳 `PARAMETER`／
两端有参数的 `UNSPECIFIED`；坐标优先／仅坐标的 B 样条裁剪反解资格尚未建立。

`CertifyCurveTrim` 先限制精确源参考，再将其私有参数域仿射对应到 binary64 端域。
共同细化与 Bernstein 界覆盖整段切点舍入及构造误差，共用原 `definitionMm`。双表示的
精确源一致性上界与实际欧氏量测分别记录；快照 `trimEvidence` 保留证据和原切点。
独立点也检查原十进制与精确单位转换后的定义误差。准备、证明、原生操作累计收费；
取消／资源不足／报告不足释放整个未发布候选，仍为 `Repair=None`。
原 `Certify` 整域和 `CertifyCurveRestriction` 实际子域证明合同保持。

曲线的精确共同细化先计算所需节点和控制点总数，再分配一份完整工作网并就地插点，
避免每个节点各自重分配整网。累计控制槽仍计入常驻参考、原副本和完整新分配；
搬移、插点、节点移动和精确算术继续计费并响应取消。物理预算及容量上限均不增加，
失败只丢弃私有工作网；张量曲面细化和末段延拓保留各自原路径。

构建检查每条曲线 LEVEL2 和实际所有权；面积、体积、材料分类及 BRep 指针检查对独立
线框不适用。存档复制并回读核对类型、节点、控制网及裁剪域；点用明确的 vertex-only
格式适配器，索引从零开始，不伪称源拓扑或材料体。native 存档不继承 STEP 验收资格。
公开 wireframe_model／wireframe_source／trimmed_spline 合同覆盖独立真值、方向、双表示、
快照寿命、复制回读、取消和预算。这些检查不授予完整 EXPRESS 或全部建模资格。

装配查看器的 v7 场景独立保存线框定义的每个实例及源集合成员；曲线、点不冒充 BRep
边或顶点。显示值按已检查的刚体实例变换转入根坐标，保留 native 参数域和源方向；
`WireframeView::CurveLength` 提供显式毫米精度的原生数值积分。该测量和显示采样均不
构成连续误差证明。场景读取完整检查全部源成员、实例归属及点变换的浮点运算包围，
才发布整份场景；缺少线框不能退回删件后的 BRep 显示。纯线框也保留零 BRep 库存。

通用开发构建器按已检查的源角色分别构建材料实体、`OpenSurfaceModel` 和
`ClosedSurfaceModel`。曲面角色不获得材料体积或 InsideSolid 资格；源层的 pcurve／旋转面
必要规则通过仍不代替对应原生工厂、几何一致性和完整发布验收。严格平面路径保留独立范围。

## 圆锥的源顶点环与计算缝

固定 AP214 通用开发路径支持一条直接完整 `CIRCLE` 边环与一个 `VERTEX_LOOP` 顶点环
围成的有限圆锥区域。顶点必须由原 `VERTEX_POINT`／`CARTESIAN_POINT` 定义，圆环、
圆锥轴／半径／半角须在原定义误差预算内建立数值对应；原顶点与实际极点的连接残差
单独使用原 `consistencyMm`，不把拓扑连接预算混作定义转换误差，也不移动原点。
边环方向必须指向该有限区域。原长度／角度单位、所有源记录与方向保持不变；该数值前置检查不是完整
源几何转换的连续误差证书。

SMLib 要求首环为边环，且该周期区域需要计算缝。目标保留原圆的完整定义和原顶点，
用一条派生直线缝两次相反使用访问源顶点环的同一顶点。源层仍有两个不同类型的环，
目标的边环不能反写成源拓扑或被称为自动修复。`TopologyNormalization().vertexLoopCuts`
独立拥有原面／边界／环／顶点身份、边界方向、目标面／顶点／缝索引，以及最终实际
原生极点连接残差和原预算；报告中的
`source_vertex_loop_cuts` 与原 `LoopMapping` 同时保留零维源用途。

全部原生消费者之后再次检查目标库存、原顶点坐标、完整圆参数区间和缝的两次相反使用，
随后仍需原生指针／LEVEL2、UV、区域、形状角色、容差和完整发布检查。闭合表面保持
`ClosedSurfaceModel`，不会因此获得材料体积。失败、取消及报告不足不发布部分结果，
仍为 `Repair=None`。复制和原生存档保留目标 BRep；存档不携带原 STEP 验收资格。

共享圆弧分段复用同一份目标库存与完整来源用途账本；实际缝索引在分段后重新绑定。
其他曲面的顶点环、多段源边环，以及与周期拓扑分割、支撑域限制或修复的组合，尚未建立
资格时明确拒绝。源类型识别不能代替这些原生构建检查。

### 显式圆锥尖点顶点校正

`Options::conicalApexRepair` 是独立的受限修复选择，默认不存在。请求绑定原件 SHA256
和完整 definition／shape／face／bound／loop／vertex／surface 身份，显式给出单点位移、
累计位移、顶点数、控制点及证明工作预算；不使用源 uncertainty 或失败后的自动阈值。
初版只允许固定 AP214 材料实体中的上述圆锥点边界，拒绝其他物理引用或多个候选目的地。

先执行完整严格尝试并保留失败，只在已确认的源尖点顶点周期近失配下构建独立候选。
校正目的地来自实际未修改原生圆锥的唯一精确极点。位移使用向外舍入上界；其他顶点、
原三维源曲线和非参与面的间距使用解析距离或正权重控制网凸包下界，连同既有最大工作
容差执行 1% 局部保护。缺少可靠间距、超预算或取消均拒绝，不能用采样补充成已证明。

候选仍需完整 UV／区域／指针／LEVEL2／角色／容差／查询检查，再与原始候选逐项比较
三维曲线、曲面定义、未请求顶点和实际工作容差。源字节与源点记录不改写。成功结果为
`AcceptedWithRepairs`；`ModelSnapshot::ConicalApexRepairs()` 拥有原／校正坐标、原始诊断、
位移／局部保护和最终请求级预算。此时拓扑规范化不能声称原 XYZ 保持不变，
`sourceVerticesPreserved` 为 false；身份仍由完整来源映射和修复收据保留。

CLI 和独立查看器使用相同的显式参数：`--apex-repair-source-sha256`、
`--max-apex-repair-vertices`、`--max-apex-repair-controls`、`--max-apex-repair-proof-work`、
`--max-apex-repair-move-mm`、`--max-apex-repair-total-move-mm`，以及每条
`--repair-conical-apex-use definition:shape:face:bound:loop:vertex:surface`。
运动预算为精确十进制毫米，原生查看器在接入场景前独立核对完整修复收据。
与其他修复、选择隔离、源优先覆盖、参数延拓、工作精度或显式周期分割的组合尚未授予资格。
关联物理线框／支撑几何范围也明确拒绝。已有源协议／单位解释在修复结果中继续保留，
修复不认证这些原声明；原生存档不携带 STEP 修复验收资格。

## 以源 pcurve 为优先表示的三维边

### 有限 B 样条载体上的 LINE 参数曲线

通用开发构建支持有限、夹持、正权重普通 B 样条曲面上的二维 `LINE`，包括作为辅助
表示的相同定义。原点、方向比和 VECTOR 幅值仍由 owning 源快照保留；UV 参数不借用
二维上下文的长度单位。直接以源十进制原点 P 和未归一化方向比 D 求 `P+qD` 与完整
存储 binary64 载体参数矩形的精确交集，不要求原点位于矩形内，不选择任意长线段或向内缩短窗口。
物理 STEP 参数为 `source_t=q*|D|/magnitude`，与 q 及 native 参数分别记录。

源十进制节点与已存储的 binary64 节点先建立参数对应：整轴逐节点证明同一正仿射图，
或在该 LINE 精确固定于原夹持边界时证明对应的边界限制。后者依赖原／目标次数和
完整夹持节点检查；边界曲线只取原控制网的首／末行，不受该轴内部节点舍入影响。
这仅建立该固定边界用途的对应，不冒充整轴仿射等价，也不把源点吸附到近邻。
上述等价规范化路径的可变轴仍须完整节点映射。无法证明则明确拒绝，不以浮点域外判定反推源错误。

若 LINE 精确固定于原夹持边界，而可变轴内部节点仅有正常 binary64 转换、无法证明
全节点仿射等价，可提出独立的待证明计划。它必须保持次数、网形和节点组／重数，
并以原始边界控制列／行、权重、节点及精确长度单位捕获源曲线；不会为证明而向外
延拓或生成拟合参考。实际比较对象直接取该载体的存储齐次网与节点，不使用近似等参线。
完整源边界与实际边界在源／原生端域仿射对应下，经过精确共同细化及 Bernstein
界证明。该路径显式要求两轴 UV 端点转换误差均为零，再仅使用一份原 `definitionMm`
验收源边界转换误差；待证明计划本身不能发布模型。
这份边界曲线证书不授予整轴节点等价或完整曲面源误差证明；最终仍核对实际完整
载体／UV 定义和真实所有权。预算不足、证明不成立或取消均释放未发布候选。

原生二维定义是 degree-one B 样条，工作参数 tau 为 `[0,1]`，精确有理数 q 端点与跨度
给出仿射对应。两端 UV 用最近偶数规则转换为 binary64；精确端值及向外舍入的误差界
保留在构建证据中。凸组合给出整段 UV 误差界，实际正齐次载体的全域导数包围再给出
毫米误差界，受原有 `definitionMm` 限制。这份界针对存储载体上的参数转换，不冒充
全部源曲面数值转换的连续证明，也不替代原有几何一致性、LEVEL2、区域与发布检查。
精确转换无需导数估计；数值容量或证据不足明确拒绝，不放宽物理预算。

`SourcePcurveLineWindow` 记录原生参数、精确 q 映射与误差界。主表示的完整载体网和实际
UV 控制点在全部原生消费者之后再次核对，并检查其真实 owning 链；
`ModelSnapshot::PcurveLineWindows()` 持有独立于调用者报告的映射。辅助比较定义不留下
悬空的 owning 证据。复制和存档保留几何，不继承原 STEP 验收资格。
空交集、单点接触或无法表示的 UV 端点不能生成候选；预算和取消也不部分发布。
解析无限载体，以及与域延拓、目标面精度、周期拓扑／支撑域规范化或修复的组合尚未
建立资格时明确返回 `Unsupported`。

通用开发构建支持 `SURFACE_CURVE.master_representation` 为 `PCURVE_S1`／`PCURVE_S2`，
参数曲线为非有理 `B_SPLINE_CURVE_WITH_KNOTS`，基曲面为平面、圆柱、已有 B 样条曲面或
有限 B 样条生成线的旋转面。按原 LIST 位置选择，重复关联不去重。目标边保留精确的
`SmCrvOnSurf`／`SmSTEPSurface` 复合定义 `S(C(t))`，不把三维拟合缓存当成定义；次数、
全部源节点及原参数域保留。所选 pcurve 与原三维辅助曲线可以使用不同参数。

参数单位由基曲面的参数含义决定：平面 U/V 按已绑定长度单位转毫米；圆柱 U 按已绑定角度
单位转度、V 按长度转毫米；B 样条 U/V 保留源节点约定；旋转面 U 转度、V 保留原
生成线参数。参数上下文不提供另一套物理单位。原 UV 值、上下文、单位、关联顺序和源
身份仍在 immutable 源快照中；`SourcePcurveComposition` 报告记录轴向比例、偏移及原
参数域。私有三维辅助定义的报告不冒充已发布目标边的参数映射。

有限计算窗口覆盖完整参数控制凸包。角向只允许全曲线使用同一个整周偏移，不逐控制点
取模。曲面参数域的完整凸包包含检查防止内核静默夹紧；未建立包含关系时明确拒绝。
包含证据不足返回 `Indeterminate`，不能仅由凸包越界推断源曲线越界或源类型错误。
旋转面可选择完整周期计算图，但仍逐值检查原生成线的系数、权重、节点和域不变。
周期缝识别要求相同源基曲面、参数控制值逐字相同的恒定 U；不能从两个端点推断生成线。
三维边界包围盒使用正权重支撑网／解析界，不借用复合曲线的拟合缓存作为覆盖证明。

辅助 pcurve 和原三维表示的所选边区间仍独立检查使用方向及图像；双向节点分段采样，超出原一致性预算
就拒绝，不能因为声明优先表示而忽略冲突。端点参数顺序及内部分段样本的单位切向检查
拒绝已观察到的反向表示；这些都是开发数值观察，不是连续图像／方向证明。
目标面 UV 仍是派生数据：可在原 NURBS 基上投影，最终使用实际目标曲面和同一边参数
复核；原曲线／曲面定义、工作容差及原有发布门槛不放宽。定义、查询、复制、二进制／
文本存档及取消的公开样件验证不授予完整 AP 或全部建模操作资格。

有理参数曲线、上述范围以外的参数曲线／基曲面、嵌套辅助 surface-curve 及单独的
曲面关联尚未建立原生构建资格时返回 `Unsupported`，不换用其他表示、裁短定义或自动修复。

文件正常声明 `SURFACE_CURVE.master_representation=CURVE_3D` 时，通用开发构建复用已有
直线、圆／椭圆、B 样条及受支持圆锥曲线裁剪的三维工厂，直接保留 `curve_3d` 原定义、
原三维参数约定与所选边区间。不会改用非线性 pcurve 的边参数，亦不拟合新的三维定义。
每个关联 pcurve 仍须在已有源工厂范围内，逐项检查端点、使用方向及双向节点分段图像；
不因其为辅助表示就忽略冲突。缺失数值证据、未知关联形式及嵌套 `surface_curve` 仍拒绝。
反向 `TRIMMED_CURVE` 的 wrapper／basis 方向与 EC／OE 在构建使用前组合；辅助比较保留
原定义和参数，以显式方向映射核对切向，不通过任意排序或反转掩盖源方向冲突。

`SurfaceCurveMaster3d` 映射关联 wrapper、原 `curve_3d` 与目标边；具体单位和参数换算由
该三维基定义的既有映射记录。辅助 pcurve 使用 `SurfaceCurveAuxiliaryPcurve…` 映射，
保留其原参数、曲面、单位与实体身份，不宣称目标边参数与它相同。模型的 owning 源快照
保留原优先声明与 pcurve 数据。最终 UV／区域、原生有效性、复制／存档、预算、取消及
完整发布门槛照常执行；仍为 `Repair=None`，本路径没有引入三维优先覆盖或源冲突例外。

### B 样条载体的等价参数规范化

通用开发构建可为 plain、clamped B 样条曲面上的非有理、clamped 二维 B 样条主 pcurve
选择一次正二进制轴缩放。仅当原 UV 曲线只触发 native 小曲率半径检查，且曲面局部
导数尺度给出非零缩放时尝试；度量采样只选择坐标图，不作为连续误差证明。
源域包含检查先于规范化。曲面全部 XYZ/W、pcurve 的 t 节点与边区间保持不变；
曲面 U/V 节点及对应 UV 控制坐标必须逐值通过二进制往返与完整存储网核对。
它保留理想三维复合定义，不增加几何误差预算，也不改变源主表示或启用修复。

载体和目标面在被拓扑接管前独立构造。每个源曲面至多选择一个坐标图；其他已有合法
载体可保留其独立参数图。派生 trim 从三维边投影到实际目标面，不能直接假设两个
载体 UV 一致。完成投影、查询及 native 验证后再核对实际所有权与完整定义。
`ExactBinarySplinePcurveChart`／`ExactBinarySplineFaceChart` 参数映射记录源身份、
二进制指数、原／目标域和度量选择位置；owning `ModelSnapshot::SplineCharts()` 保留
对应记录，独立于调用者报告寿命。原 STEP 字节及原 UV 始终由源快照保留。

当前只覆盖共最多 4096 个曲面控制点、4096 个曲线控制点及每定义共 8192 个节点的
范围；非精确可逆缩放不接纳，native 成功却改变定义则拒绝。原生调用、存储比较和
最终核对计入请求预算并响应取消。不与域延拓、目标面精度、周期拓扑规范化、裁去
未用支撑域、方向修复或圆柱带修复组合。公开样件检查完整导入、独立面积、复制和
二进制／文本存档；这些检查不授予所有模型或建模操作资格。

## 原件限定的三维主表示开发解释

## 原生边界极点的区域准入

通用 development 路径可检查有限 B 样条生成线的单周期、未交换 U/V 的旋转面图。
自然域极点只能位于 V 两端；原生近似极点 mask 必须与数值零极点 mask 相同，每个极点
必须由该面原有的源顶点标记，缝、环包含、方向及完整原生验证继续执行。这里的原生
数值分类不证明源定义具有数学上精确的极点，也不证明曲面内部没有其他奇异性。

`SmFaceProps` 在已有极点标记时可能不执行内部跨极点搜索；其默认 `false` 不能作为
无跨越的证据。因此逐一检查实际定义边／边界极点对，不因别的边已有极点顶点就跳过。
当前对以存储的有限正权重 NURBS 定义普通参数的 `SmBSplineCurve`、圆和椭圆使用其原网；
有界直线则从原解析点、方向、比例及普通参数到 STEP 参数的映射直接作精确证明，不能
把经舍入的端点缓存当成其解析定义。组合曲线、offset 等类的拟合缓存不作为定义；
尚无对应证明的曲线明确 Deferred。

实际 `SmCrvOnSurf` 的支撑若为 `SmSTEPSurface` 包装的旋转面，UV 和原生成线均为有限、
夹持、C0 以上连续且正权重的原生 `SmBSplineCurve`，可直接检查该定义组合。次数范围为
1—17，原参数、控制系数、完整单位及源优先声明不改；不换用三维辅助曲线或拟合缓存。
完整 UV 控制凸包须包含于实际 STEP 支撑域，排除内核夹紧参数的情况。生成线的 STEP
求值沿用此原生类型的普通 t，不将解析／offset 生成线的 NURBS 缓存冒充定义。

该组合使用逐操作向外舍入的区间界，分别包围 de Boor 值、导数及所有可能被 V 穿过的
节点跨度。先计算实际框架的 Gram 残差，再包围距离平方及其导数；不假设存储轴完全
正交或原生极点中心精确在旋转轴上。三角函数采用全角度界，未知区间最多细分 16 层；
半径仍为原有面工作 zone。只能建立连接至获准原端点的访问组件，内部返回、相切、
整边落在球内或任何证据不足都不放行。要求 binary64 最近舍入和渐进下溢，每次成功的
应用回调后重新检查浮点环境。该证明针对存储定义，不包含浮点评值器的连续舍入误差。

证明使用实际边参数区间和原有面工作 zone 半径，按精确 binary64 有理数进行节点插入、
Bezier 分段及有界细分。对齐次定义 `H=(X,Y,Z,W)` 和原生极点 `P`，检查
`D=(X,Y,Z)-P*W`、`|D|²-r²*W²` 及距离平方导数的 Bernstein 符号，证明极点容差球的
访问只连接到获准的原拓扑端点，且曲线确实离开该球。未获准的中间访问、切触或证据
不足均不接纳；没有扩大半径、移动顶点或生成新的分割。该证据仅针对实际目标定义边
和原生边界极点 zone，不提升为全部源几何或整个支撑面的规则资格。

显式 `FACE_OUTER_BOUND` 也必须经过极点检查，其声明还须与区域分类一致。验收记录在
全部原生消费者之后，重新使用最终的面索引、极点、zone 和实际边区间生成；不会把
先前的证书直接附到后续转换后的几何。该族与显式周期拓扑规范化、支撑域裁剪或已有
拓扑规范化的组合尚未资格化，实际极点面遇到这些组合时明确拒绝，普通无极点路径不受影响。

上述整数精确计算及组合区间证据均受请求共享的 `Limits::exactWorkUnits` 约束，CLI 为
`--max-exact-work-units`；不混入原生调用计数、物理误差或修复预算。零上限禁止该项
计算，不阻塞未进入极点证明的既有路径。取消、截止、存储容量和整数容量仍分别处理。
报告仅在实际进入时增加 `exact_geometry_work`，成功的面另记录
`revolution_pole_visits`；组合检查另记 `composed_edge_pole_pairs`、`composed_interval_regions`
和 `OutwardIntervalDefiningUvRevolution`，不计入原有 `bezier_patches`。
`ModelSnapshot::RevolutionPoleVisits()` 持有对应 owning 值，
清空调用者报告后仍存在。建模副本及原生存档保留几何，不继承这份 STEP 验收资格。

这是源角色保持的区域准入：开放／闭合表面不因此升级为材料实体。原 pcurve、优先声明、
定义和参数继续保留；默认路径及任何显式原件解释都须通过最终 LEVEL2、同参数 lift、
角色、工作容差、量测、完整报告和提交检查。

公开的 `source_pcurve_revolution_pole_driven_patch.step` 保留 `PCURVE_S1` 主表示，验证独立
球面片量测、查询、建模副本、二进制／文本存档、累计工作与报告 N／N−1、取消和完整
发布。数学合同另含非恒定 U／V、不同权重、节点穿越、非正交框架、偏轴球心及 128 个
由解析锥面和线性 V 独立确定访问组件的正反例。这些证据不授予其余曲线类型或完整 AP 资格。

旋转面的普通 NURBS 构造保留非零端圈，不按绝对坐标尺度将其折叠为一点。低于圆构造入口
半径下限的控制行使用单位圆控制网的仿射旋转，保留生成线、权重及实际参数对应；不增加
精度预算。公开[原生回归](../../tests/revolution_definition/README.md)核对普通／STEP 求值、
真实极点、复制及存档。近轴非零端圈仍可能在原工作精度下触发 `SmSurface` test 5，
完整候选仍拒绝；几何一致性修复不免除面及独立定义载体的验证，不自动切换主表示或修复源定义。

## 旋转面的等价目标参数图条件化

通用 development 路径的完整 LEVEL2 失败集若全部来自面所拥有的派生二维 UV trim
`SmBSplineCurve::AssertValid` test 13，可对未交换轴的 `SmSurfOfRevolution` 尝试一次
U 图条件化；源复合曲线内部 UV、混合原生错误、修复和周期拓扑规范化均不触发。
比例独立取自完整自然域中心的 `|Su|/|Sv|`，按最近的二次幂选择 `2^k`；仅在比值超出
`[1/16,16]`、`k` 在 `[-32,32]` 且中心条件数至少改善两倍时适用。这些是图选择的
开发限制，不是几何容差或生产质量默认值，也不是整域条件数界。

映射严格为 `new_u=ldexp(old_u,k), new_v=old_v`，原 U 起点也按相同比例缩放，不绕起点
平移。完整曲面 U 节点和该面每个实际 owner 的派生 trim 齐次 X 分量逐比特验证正逆映射；
控制网／权重、V 节点、生成线、原生成线 STEP 域和所有三维边定义及边参数不变。
完整存储恒等式证明有理 B 样条表示等价，保持同一 t 的理想 lift 误差函数；它不证明
内核浮点评值的舍入误差，也不把既有采样检查提升为连续 trim 误差证书。

应用前递归排除 BRep 定义曲线借用待改曲面／trim 的别名，未知依赖形式拒绝。原始定义
副本归模型上下文持有；只处理本面实际 trim owner，mate 不重复缩放，邻面数据不改。
清除旧参数图的曲面树、裁剪树和 edge/vertex-face UV 缓存后安装全部独立 trim 副本。
随后重跑完整 pointer／LEVEL2、区域、源角色、容差、量测及最终同 t lift 检查；结束时
再核对完整存储恒等式，不能用一个警告消失代替整个模型验收。

`ModelSnapshot::RevolutionCharts()` 与按需报告字段 `revolution_charts` 保留源身份、目标面、
原／新完整 native 域、指数、原 test 13 数量和存储恒等式检查量；`nativeStepDomain`
是内核适配参数（U 度、V 生成线参数），不是原文件的原始 UV／单位。owning 快照在清空
outcome/report 后仍保留记录和原定义。建模副本／原生存档保留目标表示，不继承 STEP 来源资格。
该操作属于等价表示规范化，仍为 `Repair=None`，不提高工作容差或任何误差预算。
失败／取消可发生于应用中途；调用者必须丢弃整个未发布候选，没有局部回滚或失败后回退合同。

## 通用构建的非材料曲面角色

显式 `generalBrep` 请求可在既有受支持的几何载体上构建一个已检查的连通、可定向源 shell。
开放模型不创建 bounded region，正反两侧 faceuse 都归无限 void region 的同一 shell。
闭合表面创建一个显式 void 的 bounded region 及内外两个 shell，`material` 始终为空。
内核 `IsManifoldSolid()` 对闭合表面可以为真；这只是一项拓扑观察，不能改变源角色。

源共享边按有向使用次数保留：开放自由边一次使用、共享边两次反向使用，闭合边界均须两次。
原生后验独立核对完整对象库存、region/shell 的真实身份与 void 标记、faceuse 两侧归属、
edgeuse 的 mate/radial 和 source-selected 使用清单。同面 seam 的两次使用不能按 face ID
去重，派生 seam 也不算自由边。仍执行原有 pointer／LEVEL2、UV 配对、区域及容差门槛。

曲面仅逐几何面计算面积及面积一阶矩，全体质心按面积加权，不调用材料体积积分，也不把
正反 faceuse 算成两份面积。默认相对停止精度及显式 tighter 控制保持原合同；这些结果是数值
观察，未建立连续绝对误差界。tight bounds 保留面内部极值并允许平面某轴厚度为零。
`boundaryMm` 仍为唯一目标边长总和，包含共享边一次；它不等于自由边周长。
模型及逐面 `freeBoundaryEdges` 记录真实自由边数。`MaterialVolumeMm3`、`ClassifyMaterial`
对所有曲面角色保持空值，不返回虚构的零体积或材料分类。

general 报告及嵌套 definition／assembly 报告输出 `source_shape`、`native_role`、
`edge_adjacency`、`face_mappings` 和材料 census 的适用性；派生边的源 edge ID 为空，
同面 seam 的重复源 face ID 保留。物质体积证据与未运行／失败的检查分别表达。
面积积分和原有材料融合积分的策略分开标记，placement-only wrapper 不制造积分结果。
全部所选定义及必需报告仍在同一个取消／预算／最终提交点后共同发布。
新增角色及库存检查计入原生调用预算；既有恰好用尽的配额可能更早返回资源限制，
不能跳过这些检查来维持旧调用数字。报告不足时不发布模型；能容纳的完整失败报告仍保留。

首批不组合 surface 角色的显式修复或 `normalizePeriodicFaces` 晚期分面请求，返回
`GeneralSurfaceConfigurationUnestablished`；不能静默忽略计划或改源面方向。原有构造期 seam、
已建立的原基支撑域规范化仍须通过其自身合同。多 shell／混合角色集合不因此获得支持，
不送入材料集合入口，也不只导入第一个成员。原有材料实体融合量测路径保持。

正常建模副本和不拟合的原生存档须保留曲面空间角色、定义类型、参数及独立生命周期；
存档不继承 STEP 来源资格。`SmBrep` 旧 C++ 复制构造器的完整失败传播／清理仍是独立
资格边界，不能从两类几何 `Copy` 修复或正常回读成功推导全 BRep 失败原子性。

## 显式装配导入 C++ 接口

`StepAssemblyImport.h` 提供 `ImportAssemblyBytes`／`ImportAssemblyFile`。调用者显式设置
general 模式、质量配置和 `AssemblyLimits`：occurrences、instances 必须为正，深度从根的 0
开始计数；实例上限包含根。当前 occurrence 上限不得超过源记录预算，instances 和 depth
实现上限各为 1,000,000。无默认放宽；修复、独立定义选择／源错误隔离暂不组合。

接口对全部声明定义及 usage 根执行源归属、单位／坐标系、原生定义构建、实例展开和
完整报告检查，沿用两次报告序列化及 `Execution::Commit` 的唯一成功／取消裁决。
失败先释放未发布模型；报告预算不足不能返回模型。源解释假设保留为
`AcceptedUnderInterpretation`，不因成功构建升级为已验证协议身份。

成功的 `AssemblyOutcome::assembly` 是 owning 只读快照：`Body(definition, body)` 返回
定义本地毫米坐标下的已有 `ModelSnapshot`，重复实例共享该定义。`Instance(i)` 返回独立
数值副本，含定义索引、父实例、源 usage、所属根及到该根坐标系的旋转／平移。
不同根不存在自动推断的公共世界坐标系。清空 outcome/report 不会丢失来源或变换证据。
通过 Body 获取的建模副本仍在**定义本地坐标**；没有自动实例化建模副本或装配存档接口。

仍明确拒绝。该 development 接口不授予完整 EXPRESS 或连续 UV／变换误差证明。
现有自动文件导入不切换到此入口。独立查看器可显式传 `--assembly`，并按需显式选择
`--unreferenced-placement-policy RetainDisconnected`；其显示范围与资源限制见查看器 README。

`step_semantics::UnreferencedPlacementPolicy::RetainDisconnected`；默认 `Reject`。

## 装配变换的内部数值候选

`StepImportAssemblyPlacement.h` 的 `EvaluateAssemblyPlacements` 消费 owning 的
`AssemblyInputs`，按其已检查的上下文身份复用既有精确长度换算器。每个换算链的原始因子、
精确比例和单位身份保留；不接受调用者随意提供的尺度，也不借用另一个上下文的单位。
当前仅求值已绑定的 `ITEM_DEFINED_TRANSFORMATION` 两端 `AXIS2_PLACEMENT_3D`。
与已有几何构建共用源数值解析、范围检查及 `build_axes/FIRST_PROJ_AXIS` 实现。

两端原点各自换算为毫米，方向比保持无量纲。输出是 **child-mm → parent-mm** 的行矩阵
`R_parent * transpose(R_child)` 和平移 `o_parent_mm - R * o_child_mm`；不是世界变换，
不能再乘一次单位比例。源关系反向由绑定身份决定，重复 usage 保留为不同记录。
坐标系缓存同时使用 item 与 context 身份，避免同一 item 在不同单位上下文间串用。

内部候选保留源输入所有权、精确单位证据及每个 usage 的数值矩阵。有限性和旋转正交残差
只提供浮点算术检查，不是毫米验收预算或连续几何误差证书；不会把矩阵拟合回旋转。
不支持的 frame 类型、非正换算、范围溢出、实例数限制或任一合作取消都丢弃整个候选。
该步骤不执行原生调用、不展开嵌套实例、不批准 pending 元数据、不建立完整定义归属，
也不授予装配导入成功或新增 CLI 接纳路径。完整源闭包、定义几何、嵌套实例、原生验证
及最终发布仍须分别完成。

`ExpandAssemblyInstances` 在显式选择的已声明 usage 根下展开数值实例候选。每个根使用自身
毫米坐标系，不推断不同根之间的位置。重复定义沿不同父路径保留不同实例；以父实例索引
和源 usage 记录路径，不复制完整路径数组。迭代展开限制实例总数（含根）和深度，防止
无环定义图的重复使用导致指数级展开。未完成的分支不会被截断后当成成功。
矩阵按父实例变换乘局部变换组合；无效根、重复根、数值范围失败及合作取消全部拒绝
完整候选。此步骤仍不构建 BRep、不批准源闭包、不提供选根后的源错误隔离，也不改变
现有 CLI 的装配接纳范围。

`BuildAssembly` 是内部、未发布的原生候选构建器，只接受通过完整源闭包的
`AssemblyDocument`。每个几何定义复用 `BuildGeneral`／`BuildMaterialCollection` 构建一次，
重复实例引用定义并保留实例树变换；不把位置写回原始定义，不做 Boolean union。
显式放置容器保留定义／实例节点而不创建空实体，也不声称完成了容器的数值积分。
定义及实体报告复用现有观察、共享调用预算和失败回收机制；后续成员失败时整个候选丢弃。
当前候选要求 general 模式、无修复／选择隔离，关联线框和构造几何仍明确拒绝。
调用者持有原生串行锁并负责最终报告和提交点。本内部返回值不等于已发布导入结果；
公共装配入口在其上完成报告和提交；CLI 接纳与实例存档格式仍待接入。

`CaptureAssemblyEvidence` 把完整候选的定义／形状身份、上下文精确单位证据、局部变换及
实例父路径提取为只读元数据；不保留任何原生 BRep，所以失败报告不会阻止候选清理。
`SerializeAssembly` 复用同一个有界报告写入器，输出独立的装配 development 格式和
逐定义检查范围。源哈希不匹配、成功状态缺少定义检查或字节预算不足时整体失败并清空
输出；既有非装配报告格式不变。公共入口在最终提交前完成该报告；仅调用内部序列化
函数本身仍不代表已通过请求提交点。

## 角环面／自交环面支撑的原基提取

通用开发导入可显式选择已有 `restrictUnusedSupportDomains`（CLI／查看器
`--restrict-unused-support-domains`），处理 `major_radius <= minor_radius` 的有限、
已证明不穿过旋转轴的裁剪区域。默认路径仍保留原来的环面范围保护。
此能力没有授予完整奇异环面、缺失区域证据、源错误修复或闭合表面升级为材料实体的资格。

候选保留完整源解析定义、单位、方向及共享三维边。先保留原生解析环面和其角度转换器，
再从同一完整 NURBS 基构建私有候选，避免解析投影产生“曲线图像正确、边参数配对错误”
的派生 UV。普通环面在该显式配置下也可在经逐值核对的原基副本上投影，测量仍针对真实
目标曲面；不改其解析目标类型。没有拟合或改写定义曲线／曲面。

图选择只改变一个完整周期的计算坐标窗口。端点评分和切口选择不构成接纳证据。
提取前必须有唯一显式外环，派生 UV 在展开图中按内核参数分辨率闭合且不借用周期跳转；
正权重控制凸包覆盖完整边界。原生成线在实际保留区间内须有严格正或严格负的半径界，
并与轴保持大于定义误差上限的余量。正／负两个正常参数分支都保留源面朝向。

随后仅对普通 NURBS 原基执行子域提取，用向外区间公共节点细化与 Bernstein 界，
对整个实际保留矩形证明相同 native UV 的曲面差异不超过显式 `definitionMm`。
不调用会重新生成并改变同参映射的解析面裁剪。安装时恢复原派生 UV 副本，不增长工作容差；
最终配对误差、区域／拓扑、有效性、量测及全请求发布门槛仍须通过。
连续证书只覆盖曲面原基提取；现有开发路径的 UV 配对／积分观察不因此升级为连续证明。

`ModelSnapshot::SurfaceNormalizations()` own 来源面／曲面、目标面索引、原／保留 native 域、
原生计算图的解析角度域、生成线半径界及连续差异证据；角度域不是改写后的 STEP 参数。
原解析原生定义也由模型所属上下文保留。
清除 outcome/report 不会丢失这些内容。报告按需输出 `surface_normalizations`，
失败报告中的私有候选观察不代表已发布模型。未建立的图、控制凸包、规则性或连续证据
分别报告数值不确定或未支持；资源限制及取消仍释放整个未发布请求。

当前不组合晚期周期分面、极点拓扑改写或显式修复。源三维参数、身份、单位和角色不变，
本操作属于目标表示规范化，仍为 `Repair=None`。建模副本及原生存档只含规范化后的目标
BRep，不继承源解析定义、STEP 资格或归一化报告；需要源语义时须保留 owning 快照。
内部 C++ STEP 接口布局扩展，库及消费者须一并重建；内核 ABI 不变。

## 完整圆环的目标分段与圆柱／圆锥图切口

通用构建可把圆柱及有限圆锥上的两条完整名义 `CIRCLE` 边界打开为一个目标图环。
圆锥两端半径必须有限且为正；半角通过已有单位绑定换算为物理弧度，切口按轴向毫米计算，
不把 STEP 的母线距离参数等同于目标轴向 V。球极点、穿过圆锥顶点及任意边界没有因此获得支持。
源闭合表面的角色不变，通用材料构建的既有范围也不扩充。

两条圆环起点相位不同时，先在任何面构建前形成全局分段计划：保留原顶点，在另一圆的
**原生原基参数**处加入派生顶点，并让全部相邻盖面／侧面共享相同子边。每个子边保留完整
原解析类、齐次控制网、节点、自然／STEP 参数域及解析辅助数据，只限定自己的 edge interval；
不裁短、重建、重设圆相位或重参数化定义曲线。各子区间必须逐端点精确相接并覆盖完整原使用。
同一源圆上的多个切点也在全局排序后共同展开，派生点不伪造源实体身份。

切口沿固定经线／母线。新点反求的数值残差受原 `definitionMm` 约束；无法区分的近端参数
使用独立的内核参数分辨率保护并拒绝，不能用毫米误差预算替代。原源点逐值保持，子边及
全部目标库存仍通过原有 UV、邻接、容差、原生有效性、量测和最终提交检查；没有放宽质量预算。
派生 UV 仍是既有开发数值观察，不因区间覆盖正确而获得连续提升误差证书。

两完整圆边界的有限圆锥还可把计算切口移离已有源顶点。仅当原切口端点与源顶点的差异
超过定义转换误差时规划；不改源顶点、圆边、圆锥或工作容差。最多检查三个固定经线，
旧顶点必须离开原生分类器的吸附区，两源圆都按原 `definitionMm` 定位内部参数。新增的
目标顶点位于圆锥切口，其与原圆在对应参数处的连接偏差另受已有 `consistencyMm` 约束，
沿用周期拓扑规范化中 `PeriodicNormalizationDerivedVertexResidual` 的连接语义；这项偏差
不是定义曲线的转换误差，不会放宽 `definitionMm` 或移动任何已有点。
两圆全局分段后仍保留全部完整原基。最终消费者结束后重新检查新节点连接，模型快照内
独立持有参数、实测偏差和原预算，必需报告记录 `ConicalDerivedVertexConnection`。
`ConicalCutAwayFromSourceVertexGaps` 标明切口来源；任何未建立参数、超预算、无合适经线
或原生有效性失败仍拒绝。原生第 36 项及导入区域检查照常运行。公开带连接偏差的圆锥
用原顶点／完整系数、参数覆盖、复制与存档、容差带体积包围及超预算反例验收；不把容差
BRep 宣称为具有唯一精确体积的闭合点集，也不授予完整源几何或 EXPRESS 证明。

圆柱的两条圆环也可分别由多个直接 `CIRCLE` 源边组成。规划要求每环按源顶点身份闭合、
圆弧共轴／同半径且处于各自同一高度，并按已组合的源方向分别绕行完整且相反的一周。
这些数值准入条件只选择构建分支，不代替完整源曲面一致性证明；最终物理预算和原生检查仍须通过。
若所选经线落在一条开圆弧内部，该弧全局分段后仍保留两个不同的源端点；所有相邻面共享
同一组子边。构建按完整源环展开子边后循环移位，不能只把单条圆弧的头尾直接拼接。
报告以 `PeriodicCutFromFragmentedCircularRings` 记录这项等价切口。已存在合适源顶点时不增加
分段；一般非圆边界、绕行不明、切点不唯一或尚未证明的圆锥多弧组合不属于本扩展。

圆柱还支持一条完整同轴圆边界与一条由直接 `CIRCLE`、`LINE`、B 样条组成的混合边界。
在任何真实面采用源曲线前，用完整几何副本建立临时单面，沿原圆顶点的经线分类；只接纳
唯一面内区间，另一端必须是另一源环的已有顶点或圆弧内部点。源圆弧与该点的毫米残差
受原 `definitionMm` 限制，近端参数仍受独立参数分辨率保护。环绕、相切、近缝或交点证据
不足不会触发该分支；不为 B 样条内部交点猜测裁剪参数。
分类器可能把区间端点吸到计算支撑边界，因此使用其保留的 `GetPreSnapParam()` 重新求值
并检查毫米残差，不把工作容差的吸附结果当成源顶点。调查副本逐项检查原定义的复制身份，
共享原生调用、容量及取消约束，退出时完整释放；它本身没有发布资格。
选定的圆弧切分与既有圆环计划一起全局冻结，复用完整原基及全部相邻面的同一子边，
记录 `PeriodicCutFromMixedCylindricalBoundaries` 和 owning 使用映射。公开阶梯圆柱按独立
面积／体积、台阶内外查询、原顶点与完整系数、建模副本及存档回读验收；这些检查仍不授予
连续源几何误差或全部 AP 资格。所有源 pcurve、优先表示和原有物理预算保持原合同。

`ModelSnapshot::TopologyNormalization()` own 完整目标面／边／顶点来源。实际一对多使用还
保留 `sourceUseSegments`：原面、边界、环、有向边、边身份及方向，对应目标子边／顶点和
原基子区间。只清除 outcome/report 不会丢失；报告在 `topology_normalization` 中条件输出
`source_use_segments`。相位对齐的新圆锥图也保留派生切口来源，无分段时不制造使用分段记录。

这是已有等价目标表示规范化的扩展，无新自动修复选项。合法源保持 `Repair=None`；源中的
多外环错误仍须已有显式、SHA256 绑定的圆柱带角色修复，原错误和原文继续保留。新图规划
与晚期周期分面、支撑域限制、面朝向修复或球极点的组合尚未建立时明确拒绝。所有所选目标
仍共同提交，取消、原生／报告预算或任一后验失败均释放未发布候选。

内部 C++ `TopologyNormalizationInfo` 布局扩展，STEP 库和消费者需一起重建；内核 ABI、
原生存档格式及原生存档／建模副本不继承 STEP 资格的规则不变。

## 精确有向圆柱带的边界角色修复

`Options.cylindricalBandRepair`／CLI 单文件显式计划可选择 `ExactOrientedCylindricalBand-0.1`。
请求必须绑定原始 SHA256，逐项给出定义／形状／面及原有两个 `FACE_OUTER_BOUND` 的身份，

该配置暂不与面朝向修复、定义选择、限制支撑域或额外周期分面请求组合。

源层真正执行原 `FACE.WR2` 谓词并保留失败。只有计划与全部所选源使用匹配，才允许继续其他
类型、单位、依赖及归属检查；输出为 `DeferredExplicitRepair`／`ExplicitRepairPending`，
不是合格源声明，也不是非几何属性例外。缺失／重复／错误／不必要计划仍拒绝，任何其他源错误
保持原行为。原记录、类型、顺序、数值、单位、方向、边／顶点身份均不改写。

原生分配前，用固定 4096 位有界精确有理数证明：两个环各由一个完整闭合 CIRCLE 边构成，
圆心精确共轴，圆法向平行圆柱轴，半径精确相等且为正，高度严格分离；组合源边、使用、边界与
面朝向后，下环沿正角向、上环沿负角向。此有向边界在 `S1 × R` 上唯一确定有限圆柱带，
而非它的补集。不通过采样、浮点 epsilon 或容差增长获得该结论；不满足精确关系、资源不足或
其他曲面／裁剪边界均不授予该修复资格。

目标只中和两个互相矛盾的显式外环提示，保留全部原有环与使用方向，再由现有区域分类验证目标。
既有隐式经线图切口继续保留来源映射；需要尚未支持的圆环分割或 UV 超预算仍拒绝。
在 UV 创建前私有复制原生三维定义，最后逐对象比较全部顶点、曲线／曲面定义、参数域、
控制网、权重、节点、解析参数和工作容差，要求完全一致。未声明移动／拟合／缝合。
这是有向有限带的独立源区域证明及原生后验，不声称所有源 AP 规则或连续 UV 误差都已证明。

完整模型返回 `AcceptedWithRepairs`（CLI 12）。`ModelSnapshot::CylindricalBandRepairs()`
own 原始错误、原件身份、逐面证明身份与三维／容差比较结果；清除 outcome/report 不丢失。
`Source()` 仍能读取原始两个外环类型及未消除的源错误。建模副本和原生存档不继承 STEP 修复资格。
所有体／定义仍共同提交；取消、截止、证明／原生／报告预算不足或任一后验失败均释放未发布候选。
源原始错误计入源诊断总预算；精确证明运算与原生对象比较在整个请求累计，逐控制点只读访问仍
受源输入／对象容量约束，不冒充原生求解器调用次数。

参数为 `--band-repair-source-sha256 HASH --max-band-repair-faces N --max-band-bound-edits N`
`--max-band-proof-operations N`，重复 `--repair-cylindrical-band DEFINITION:SHAPE:FACE:BOUND0:BOUND1`。

内核 ABI 及原生存档格式不变。

执行有效性／定义／UV 验收；这不是 STEP 来源资格的持久化。
通用回归要求回读曲面、三维曲线及 UV 曲线类型一致，继续比较完整系数、节点和边参数，
不再借用历史解析识别作为回读类型例外。旧 `SmBrepData`／`SmApiReadPartFromFile`
入口保留原来的识别与 healing 行为，不能用于声称上述存储定义保真。
使用此新入口的消费者需要与包含该符号的新内核 SDK 一起链接；C++ 布局与文件格式不变。

发布保留两次报告序列化：首次确认报告可生成，后一次记录最终检查点观测；提交成功后只移交
模型所有者，不再分配、回调或调用内核。失败先释放候选再生成失败报告，报告预算不足不覆盖取消终态。

内核首环必须为外环；仅将源 SET 中的外环提前，源身份与声明方向不改，规范化政策显式记录。

模型没有编辑或 native 指针接口，面视图强引用模型，报告不保活 native BRep。

当前范围限定为两个简单直线外环界定的平面区域，可各带零个或多个直接孔，

源层先证明各孔简单、严格位于外环内且互不相交、接触或嵌套；中立计划要求所有孔顶点
也精确位于定义平面。扣除孔不会增加两面交集，共享边须同时属于两个外环。

有孔矩形只以外环证明支撑边，不能把净面积与完整矩形面积比较或用外环替代实际面。
共面时先证明支撑平面一致，再判断两多边形位于共享直线的严格相反半平面；
不依赖某个世界坐标投影或native validator代替区域证明。
同侧重叠、完全重合、内嵌、跨越共享直线或额外触线的外环、共享孔边、更多面及缝组合仍不在此目标范围内。

构建复用同一个native edge，各逻辑使用保留自己的方向与SAME-owner UV；每边分别核验2/4个native EU、
mate/radial关系、实际相邻面和自由边身份，不能只核对全局数量。
整体面积、面积形心和bounds包含两个面，整体normal/window为空；`Faces()`保留各面的法向与参数域，

三角形、梯形、凸/凹五边形及含共线顶点的边界沿同一构建路径保留全部顶点和有向使用；
实体数量、自由边和容差观测按源拓扑变化，不补成四边形或取凸包。
附加支撑边、关联证明及native邻接输入表按边界大小线性建立，原源区域检查的计费保持。

普通失败与调用/报告限额不会交付部分模型，结果中的诊断区分源拒绝、目标不支持、数值证据不足和 native 失败。

## 构建与验证

### 执行、取消和独立副本

`Options`及文件路径在同步调用入口冻结；原始字节在捕获后不再读取路径。
`execution.control`可指定一次性的`ImportControl`。其他线程可请求取消，返回
Requested/AlreadyRequested/TooLate/AlreadyCompleted；取消请求自身不访问native。
`execution.progress`在捕获、源检查、逐native调用间、报告及提交前同步通知。
不可中断调用先安全返回，候选撤销完成后返回Cancelled；旧快照和捕获源不变。
observer的非分配异常返回`ExecutionCallbackFailure`（BuildFailure）；意外`bad_alloc`向调用者传播，不能伪称已配置限额耗尽。

模型owner和必需报告在发布前完整准备，取消/成功由一次原子提交裁决。
成功之后迟到取消返回TooLate，模型寿命由快照/view持有者决定。
本模块的native构建、查询、副本、编辑回调和释放共用进程内串行锁；
其他直接native调用者仍须协调，独立context不代表整个SMLib可任意并发。

`nativeLimits.processPrivateBytes`检查进程PrivateUsage的软上限，`execution.deadline`使用steady clock。
检查发生于安全边界并在发布前复核，单次操作可以超出边界间预算；不提供OS硬保证。
`hardMemoryBytes`明确返回UnsupportedHardMemoryContract。
执行报告区分未测null、检查点最大private commit和进程生命周期峰值；后者不归因于单请求。
观测截止为最终报告序列化之前，发布前预算拒绝会记录额外失败观测。
工作内存、截止和取消与硬取消/崩溃隔离分开，生产档位仍待实测定标。

`ModelSnapshot::CopyForModeling()`返回独立结果和`EditableBrep` owner：
深复制保留几何类型/材料角色，在独立context中通过指针及LEVEL2验证后交付。
`Edit(callback)`仅在串行回调作用域借出BRep，允许非消费式原地编辑；
不能删除/消费根或保留native借用。副本释放与原快照无关，编辑结果不继承原导入质量资格。
报告和声明仍不持有native对象。进一步建模、worker和跨进程物化各需自己的资格。

### 命令行

根 CMake 在启用 `SMLIB_BUILD_VALIDATION` 时注册库和 CLI。独立 CMake 可接收已有 `SMLib` / `SM_API` targets；本机 Windows 路径使用
匹配源码、配置、CRT、宏及工具链的 SDK，目录中分别为 `release/`、`debug/` 的 DLL 与 import lib：

```powershell
cmake -S source/STEP_IMPORT -B <build> -DSTEP_IMPORT_NATIVE_DIR=<sdk>
cmake --build <build> --config Release
ctest --test-dir <build> -C Release --output-on-failure
<build>/Release/step_native_import --fixture-limits --quality Q-P0-mm-01 input.step --query 4.2 9.6 8
$env:STEP_NATIVE_BINARY = '<build>/Release/step_native_import.exe'
python -m unittest tools.step_import_native_validation.tests.test_native -v
```

CLI 返回 0 Accepted、1 Rejected、2 Unsupported/参数错误、3 ResourceLimit、4 SourceFailure、
5 必需输出未发布、6 BuildFailure/调用异常、7 Deferred、8 Indeterminate、9 PostcheckFailure、10 Cancelled。
CLI可指定源字节/记录/引用/值/深度/字符串/单记录/ID长度、语义访问和planar工作限额，
以及`--max-process-private-bytes`、`--deadline-ms`和`--hard-memory-bytes`。
CLI截止可设在24小时内；所有执行限制按上述合作性质处理。
JSON 输出为 binary stdout，字节预算不受 Windows 换行转换影响。
测试直接沿内部公开接口和真实 CLI；没有另建测试包发布机制。
Windows 资源检查包含成功、各调用预算边界、后验预算不足、报告超限及保留模型的阳性对照。
匹配共享 CRT 的串行、非 TBB SDK 下，Release／Debug 均按导入线程发起的 CRT 底层堆请求判断残留，
其他线程释放或重分配已跟踪请求仍会更新账目。保留原 4 KiB／8 块限额及真实保留模型的阳性对照；
进程总堆、全局 Debug CRT、PrivateUsage 与生命周期峰值另作诊断，不将无关线程／运行库的存活开销
直接判为模型泄漏。观察器安装、容量或恢复失败均使测试失败；不适用于静态／不同 CRT、worker
内的原生分配或虚拟分配，也不证明进程整体无泄漏。见[资源观察器合同](tests/RESOURCE_OBSERVER.md)。
导入器的资源配置与发布条件未改变；具体执行收据保留在本地。

早期验收使用 C++20 适配器配套 C++17 原生内核；该历史记录不代表一般 ABI/跨平台资格。
当前全仓构建基线为 C++20，旧验收记录不替代新基线验证。
`SmIterationValue::operator==` 仅补 `const` 以使头文件能在 C++20 equality rewriting 下编译，
函数原有恒 FALSE 主体与求解算法不变。对应头文件见
[SmLocalSolve1d.h](../SMLib/inc/SmLocalSolve1d.h)。

公开精确有理圆柱曲面控制涵盖样条边、圆弧边、解析面积／体积、真间隙反例及复制回读。

隐式球冠仅在 SPHERICAL_SURFACE 的一个显式 FACE_OUTER_BOUND 包含单个闭合 CIRCLE
使用时建立候选。轴、圆心、半径与端点须通过向内舍入的定义预算检查；曲面轴和圆轴
还须满足独立的无量纲平行条件。已合成的边／边界／面方向决定保留南侧或北侧，不按
较小面积猜测。目标上添加一条正反使用的子午线缝及一个极点，原球面、源边区间和源
顶点不改写，记录 `ImplicitSphericalPoleCut` 和 `ImplicitSphericalPoleChart`。

及相对源轴的正负方向，不填写虚构的 source_vertex_id 或源边参数。原始源顶点数组与

## Material collections

`ImportMaterialCollectionFile/Bytes` returns `CollectionOutcome` for one part's
complete registered MSB inventory. It requires the general path and preserves
one immutable source snapshot with independent native BReps. A successful outcome
owns `collection`; the existing `ImportFile/Bytes` still owns a single `model` and
retains its multiplicity refusal. CLI users select `--material-collection` and may
also select `--compact-source-report` for the mandatory report.

`MaterialCollectionSnapshot::BodyCount`, `Body(index)`, `SourceShapeId(index)` and
`Source()` expose the complete ordered inventory and owning body snapshots. A body
or its face view can outlive the collection outcome; modeling uses that body's
existing independent copy API. Body indices follow serialized representation item
order, not size or geometric priority. Shared source shells/geometry never merge
source solid identities or native context ownership. Overlapping bodies remain
separate. No aggregate union volume or material classification is inferred.

Every body uses the existing construction, installed-UV, native validation,
tolerance, source correspondence and measurement checks. One request execution
ledger charges all body work; it never resets the budget between members. The
collection and required report publish only after every body and the final
cancellation decision succeed. Failures discard all unpublished bodies while
retaining per-body observations. Late cancellation/report failure likewise returns
no collection. Separate native contexts do not imply kernel thread safety;
construction, queries, destruction and archive copying retain native serialization.

The report format is `step-material-collection-development.v1`. One root source
inspection serves all bodies. `material_collection.bodies` records source
shape/shell IDs, `checks_passed`, and `step-material-body-checks.v1` observations.
Nested source/execution evidence explicitly references `CollectionRoot`; nested
status follows the whole request and is not independent publication. On failure,
no nested `model` is published. Original source interpretations qualify the whole
collection as `AcceptedUnderInterpretation` when applicable.

`WriteNative` writes an ordered native BRep array with an empty CSG tree, using
private deep copies to protect snapshot UV data from kernel writer normalization.
Native archive order matches body order; source identities and import qualification
remain in the owning snapshot/report and are not conferred on an arbitrary native
archive load. Archive readers must validate all bodies and their defining geometry.
The CLI supports collection `--write-native`; queries require explicit body selection
through the C++ API.

Current scope is body-only material collections in one part/common representation
context. Assembly transforms and collection-level associated wireframe/construction
ownership remain unsupported. Mixed requests return
`MaterialCollectionAssociatedGeometryUnimplemented` before constructing bodies;
source surface models are never upgraded to material solids. The standalone viewer uses canonical part dispatch for complete collection scenes.


The reusable collection controls use public synthetic fixtures:
`tests/fixtures/two_material_boxes.step` contains two 10 x 20 x 30 mm boxes
with a 100 mm X translation. Each has volume 6000 mm3 and area 2200 mm2;
their centroids are (7, 7, 20) and (107, 7, 20) mm. The source carrier derives
from the public P0 analytic box; the independent generator is
`tools/step_import_native_validation/tests/test_material_collection.py`.
`tests/fixtures/box_and_cylinder.step` adds a radius-3, height-7 mm cylinder
(volume 63*pi, area 60*pi) overlapping the box. Its purpose is to verify separate
body identity and an empty native CSG tree, not a union-volume assertion.
Collection contracts include exact defining coefficients and installed UV after
native archive readback, independent copies, shared source shell identities,
late/second-body cancellation, cumulative budgets, second-body failure and
mandatory-report cleanup.


`ImportPartFile/Bytes` returns `PartOutcome` with a typed `PartModel` variant:
`monostate` on failure, an owning single `ModelSnapshot`, or an owning
`MaterialCollectionSnapshot` on success. It requires the general path. Source
capture/check runs once; the checked inventory selects the construction path.
Single-body associated geometry keeps the existing owner/export behavior; multiple
material bodies use the collection contract above. No retry/reparse or source
interpretation fallback is introduced. Both publication alternatives are prepared
before the one commit point; final variant ownership transfer is nonthrowing.


显式 `CarrierInterpretation::BlankLevelAsCorrectedEncoding`／CLI
`--interpret-blank-level-as-corrected` 可为实现级别声明为空字符串或纯 ASCII 空格的输入
选择现有纠正编码语法。它要求 general 非几何互操作配置；原始声明、错误诊断和未验证
身份保留，成功仍为 `AcceptedUnderInterpretation`。默认及旧 level1 选项不接纳空白声明。
类型、物理单位、几何和原生验收继续执行，不自动改写声明或重试另一编码。


显式 `Options.unitInterpretation=VerifiedExplicitUnitDimensions`／CLI
`--interpret-explicit-unit-dimensions` 支持经精确验证的 AP214 SI／换算长度、平面角单位派生槽位引用。
它要求 general 非几何互操作配置，默认关闭。单位指数、换算依赖、原始引用和诊断保留；
维度矛盾、循环、不支持的单位和非正换算因子继续拒绝。精确物理缩放仍由原生单位解析器
验证，容量不足仍为 Indeterminate，不能因维度一致而跳过缩放检查。

通用构建器支持 nominal `PLANE_ANGLE_UNIT` 的正换算链，必须终止于 SI RADIAN；
七维指数为零本身不能替代角度角色。与长度缩放共用原有 4096 位有界精确十进制算术，
最后的弧度比例须可表示为现有 64 位 `Fraction`，随后才转入原生浮点参数。
单位标签不参与推断：即使名称为 degree，也仅使用原文因子，不代入另一份 pi/180。
原 SI 快路径、长度单位证据及原始因子字面量保留。该换算同时用于圆锥 semi_angle、
裁剪圆／椭圆的参数，以及圆柱／旋转面的源 pcurve U；生成线参数、方向比和 B 样条
UV 不获得角度缩放。符合源派生标记的单位无需启用单位解释；非符合显式引用仍需上述
独立选项，保留全部原诊断并返回条件成功。几何一致性、源优先级、工作容差、复制存档
和原子发布检查继续适用，不授予超出已实现几何范围的资格。

源快照记录独立的单位解释证据；面、线框和支撑几何 owning view 的
`AppliedUnitInterpretation()` 读取同一证据。最终模型成功时为
`AcceptedUnderInterpretation`，并报告 `source_unit_declaration_conforming=false`。
修复仍为 None，几何定义、预算、检查、取消与原子发布保持原合同。查看器通过
`--unit-interpretation VerifiedExplicitUnitDimensions` 显式选择，并保留 HUD/扫描资格。

## Internal grouped construction

集合／独立定义的 Import report 观察生命周期由私有
`StepImportObservation.h` 的 `ObserveBodies`／`ObserveDefinitions` 集中处理：
建立 child report、继承源上下文、结算定义计数、汇总积分以及失败收尾。
成员回调同时负责构建和将成员纳入候选；只有回调成功才记录 `checksPassed`。
最终封装回调在积分汇总后执行，仍处于同一失败保护内。同步回调只在调用期间借用，
不保留回调，也不增加原生调用、检查点或执行预算。

`Execution` 仍是唯一请求账本，定义计数采用请求根计数的区间差值。体计数保留原生
构建／修复状态机的叶观察语义；`originalAttempt` 是重叠 witness，不能把任意报告
子树相加，也不能用根差值覆盖体计数。成员错误返回和意外异常都会保留已完成检查、
标记应丢弃的观察并释放未发布候选；观察收尾不执行原生销毁或发布。

上述两个批次入口、集合／文档构建及对应发布入口使用私有
`Result<T> = tl::expected<T, Failure>`，错误类别和诊断直接向上传递。
原生构建、计划证明、单位／分段／规范化及修复中的业务 `Failure` 均通过结果返回，
入口按错误值完成诊断和失败收尾，不再捕获这一类型的异常，也不把错误值重新抛出。
这不是全库禁用异常或全链路 `noexcept`。公开 Outcome、快照及报告格式不暴露
`tl`。Execution 继续仲裁最终执行结果，Publication 保留两次报告生成和原子发布协议。

依赖从仓库内固定版本构建，无配置期下载；来源及校验和见
[tl-expected 清单](../../third_party/tl-expected/UPSTREAM.json)。
回归范围及定向变异方法见 [嵌套观察测试](tests/NestedObservation.md)。

定义选择也直接返回 `Result`，保留源顺序、owning 选择收据以及选择前／完成后的检查点。
Publication 的接纳、报告容量和最终提交检查结果直接传播至入口，由公开 Outcome 的
拥有者记录诊断及完成失败收尾。Execution 的检查点、原生调用计费、修复登记／证明预算和
提交仲裁均返回结果。原生构建、精确单位算术、UV、周期处理和连续证明的必要回调链直接
传播错误，既不丢弃错误值，也不把执行拒绝转成数值证据未建立。内部结果函数标记
`[[nodiscard]]`；拥有候选的构建边界同时处理错误返回与异常退出的清理。
[执行协议回归](tests/Execution.md) 固定检查／计费顺序、拒绝诊断、最终 guard 与 CAS，
公开生命周期和修复回归核对完整报告及原始尝试的重叠计数。

平面原生构建的源对应、所有权、拓扑后验检查和保守数值证明拒绝也直接返回业务错误，
保留原诊断、证明观测及失败候选清理。公开查询异常与底层数值算术的既有分类保持独立；
验收边界和变异要求见 [业务失败回归](tests/BusinessFailures.md)。

严格方向修复尝试的私有 `ConstructionResult` 区分普通 `Failure` 和携带原生候选的
`OrientationFailureCandidate`。修复协调者显式消费 witness；普通构建边界先释放其
候选所有权，再返回普通错误供报告交付。原始尝试的重叠计数、诊断和后验比较保持原合同。
节点多重度及权重直接返回拥有数组的 `Result<SmTArray<T>>`；自有缓冲通过移动构造
进入结果，消费者检查成功后直接借用其中的数组，不产生包装／提取复制。
容器的借用缓冲、上下文及分配失败合同见 [移动构造回归](../../tests/kernel_containers/README.md)。

最终裁剪的参数检查及量测返回 `tl::expected<T, TrimMeasurementError>`，区分参数域、
节点读取、求值及非有限距离拒绝。该错误类型不携带执行取消或请求预算错误；原有派生 UV／
支撑域回退只消费局部量测拒绝，检查点的 `Failure` 仍直接传播。量测中的节点跨度、每跨度
八个子区间、实际同参数求值及参数舍入保护保持原合同。通用构建边界保留原来的
`BuildFailure`／`NativeReturnOrConstructionFailure` 诊断、消息、空源记录和阶段。
回退中保留的 `runtime_error` 捕获仅兼容底层原生调用仍可能抛出的异常，普通量测拒绝不再抛出。
回归及变异范围见 [业务失败回归](tests/BusinessFailures.md)。

原生构建、通用材料构建和独立曲线定义的原生状态检查通过 `CheckNativeStatus` 返回
`Failure`，保留平面／通用构建各自的原消息前缀及导入入口的原错误分类。必要的线／面系数
读取和包络汇总直接传播结果，原算式、表示读取次序和执行计费不变。工厂的非空输出在状态
检查前进入 RAII 所有权，失败和后续报告分配异常均不会遗失未发布对象。公开查询／存档
仍直接检查原生状态并保留既有异常合同，不将内部错误值重新抛出。
这些原生／量测操作拒绝带私有 `ConstructionOperation` 种类：严格修复协调者保留原先立即
退出时的未完成观察，不额外填写 `originalAttempt` 状态、诊断或丢弃收据；普通业务／执行
拒绝仍按原合同记录严格尝试失败。该种类不构成朝向修复 witness，也不改变公开报告布局。

通用方向归一化与坐标框架构造返回结果，材料边／曲面、独立曲线、辅助框架、接缝及球极点
调用链直接传播其数值拒绝。有限源方向的范数溢出或近平行投影无法建立原生框架时，仍为
`Indeterminate`／`GeneralDegenerateFrame`，保留原消息、空源记录、D5 和严格尝试的未完成观察。
范数、双叉积投影、归一化算式及源参数约定均不变；不通过重缩放扩大已支持的数值范围，
也不将其归入配置预算耗尽。原生计费、已执行／未执行校验的记录和候选释放保持原合同。
标量文本、三元坐标及毫米坐标转换同样直接返回结果；原 `from_chars` 的解析、上溢／下溢
拒绝、前导正号处理、三维要求及一次长度缩放保持不变，不钳制数值或补造坐标。
`GeneralNumericRangeUnestablished`／`GeneralRequires3DGeometry`／`GeneralLengthRangeUnestablished`
保留原来的 `Indeterminate`、消息、空源记录与 D5。节点数组也通过拥有缓冲的结果返回，
使用者检查成功后借用其中的数组，不依赖移动赋值或引入提取复制。
私有 `SourceValueConversion` 来源保留严格尝试的未完成观察，并让装配位置求值保留其原有
标量转换消息、位置实体与 `AssemblyPlacement` 阶段；原坐标框架归一化错误继续保留其不同消息。
材料、独立曲线／点、样条及装配路径共享同一数值读取规则，不另造源解释或改变原生计费。

迁移目标是消除项目主动创建的异常，以显式结果表达业务、配置及内部失败，
而非按异常类型名筛选：
项目显式抛出的 `std::invalid_argument`／数值错误同样属于待迁移范围。
当前公开配置／查询及存档异常合同、其余内部前置条件拒绝、底层数值不确定性／容量哨兵和共享 JSON writer
内部超限终止仍未迁移；数学证据未建立与工作空间不足继续保留各自的证明结论，
不能与请求取消或业务失败混同。
STL／运行时实际产生的异常及外部回调异常另有传播或边界转换合同；
不能用全局 `noexcept` 或禁用异常编译选项代替逐层迁移和验收。


## 显式源 pcurve 载体工作精度

`Quality::GeneralPcurveCarrierPrecisionStudy()` 是独立的开发质量配置，CLI 标识为
`Q-AP214-pcurve-carrier-precision-study-mm-01`。它保留 `GeneralDevelopment` 的
几何、派生 UV、查询、拓扑工作容差和修复预算，只为实际拥有的
`SmCrvOnSurf` → `SmSTEPSurface` → `SmSurfOfRevolution` 载体显式选择 `1e-11 mm`
数值工作区。该值是实验分辨能力，不是生产默认值或浮点误差证书；不由源 uncertainty
推断，也不在失败后自动重试。未选择时，原生默认行为和报告字段保持不变。

源生成线、源 pcurve、单位、参数域、优先声明及拓扑容差均不改变，不把近轴圆边界吸附为点。
`SmTol` 对该拥有支撑读取显式值与系统区间的较小者；不改变线程／进程默认值。
配置记录在曲线的唯一、单用户 COPY 属性中，以版本号和整数编码的 binary64 保存，
避免文本存档的小数精度丢失。复制和两种存档保留该值；正均匀缩放同步缩放存储的长度，
有效工作区仍不宽于系统默认。非均匀缩放、非正缩放和非刚性／非有限坐标架在编辑前拒绝。
底层支撑或通知在编辑开始后失败仍沿用内核的非事务性合同，不承诺任意失败回滚。

报告 `pcurve_carrier_precisions` 区分构造用的辅助比较载体与实际定义边；
`ModelSnapshot::PcurveCarrierPrecisions()` 只交付后者的 owning 记录，独立于报告寿命。
复制与原生存档仍不继承 STEP 资格。源一致性、完整 L2、最终 UV／区域、质量和预算、
必要报告、取消及原子发布门槛全部保留；启用这项数值配置本身不代表完整原件导入成功。
与周期拓扑规范化、支撑域限制、修复或定义筛选／隔离的组合尚未验收，配置阶段拒绝；
收据中的目标边索引因此始终指向未重排的原始构建边。

## 显式目标旋转面工作分辨率

`Options::targetSurfacePrecision` 是独立、默认关闭的通用导入开发解释，声明见
[`StepImportSurfacePrecision.h`](inc/StepImportSurfacePrecision.h)。请求必须同时给出不可变原件
SHA256、非零目标面数量上限、模型毫米单位的正 `int64` 分子／分母，以及每项精确的
源定义、形状、面和支撑曲面实体身份；不从文件名、原件 uncertainty、已有载体精度或失败结果推断。
只作用于计划实际绑定并拥有的旋转面目标计算支撑，不为其他面或进程／线程默认值设置精度。
当前仅原生奇异性分类的数值退化阈值显式使用该分辨率；`SmTol` 的几何相合、交线及近似容差
保持原值，接缝、端点与拓扑一致性判断不能借此改用更紧或更松的物理阈值。

这项数值计算分辨率与源 pcurve 载体工作区独立，可与上述显式载体质量配置组合；选择该质量
本身不会启用目标面请求。源生成线／曲面定义、控制点、单位、参数域、源 UV、优先声明、拓扑
及其容差均不改写，几何验收、派生 UV、查询及修复预算均不增加。不吸附近极点边界，不将
细圆环折成点，不跳过或降级任何原生检查（包括 `SurfaceTest5`），也不在失败后自动重试。
原生计算仍须通过原工作容差／物理预算、最终 UV／区域、指针及完整 L2、复制／存档、
必要报告、取消与原子发布门槛。分辨率数值不是浮点舍入界、曲面正则性证明、源 schema
一致性证明或连续误差证书。

请求仅在通用路径使用，允许与显式终段参数域及源三维优先解释组合。与修复、定义筛选／源错误
隔离、周期拓扑规范化及支撑域限制的组合在配置阶段拒绝。原件不符、面／曲面归属不符、
未建立实际拥有的受支持支撑、未命中的计划或未通过普通原生检查，都不发布模型；
不得把范围错误或数值证据缺失当成可由提高分辨率消除的缺陷。

CLI 的四类参数必须完整、显式提供；标量不可重复，面计划可以逐项重复该选项：

```text
--target-surface-work-source-sha256 HASH
--target-surface-work-resolution 1:100000000000
--max-target-surface-work-faces 1
--target-surface-work-face DEFINITION:SHAPE:FACE:SURFACE
```

分辨率文本只接受正整数 `NUMERATOR:DENOMINATOR`，不接受浮点或科学计数法；原整数比在收据中
保留，不静默约分。所有计划完成且全部导入门槛通过后，状态为 `AcceptedUnderInterpretation`
（CLI 11），`Repair=None`。`ModelSnapshot::TargetSurfacePrecision()` 保留 owning 只读收据，
独立于临时报告寿命；原生存档与独立建模副本不因此继承 STEP 资格。

JSON 根的 `target_surface_precision` 保存原件、质量标识、精确分辨率、数量上限、全部计划和
实际动作。每项动作区分请求分辨率、实际生效分辨率、原拓扑面容差和原生检查完成状态；
`target_face_index` 是该快照内部构建面的索引，不是源实体号或编辑后的稳定身份。嵌套报告只以
`source_sha256` 与 `receipt_scope=RequestRoot` 引用同一请求根，不复制尚未完成的资格。
根在接纳前核对全部计划的一一完成、原件／质量身份与有限数值证据；失败收据不冒充成功。
未提供请求时不增加该 JSON 字段，默认导入行为保持不变。

同原 NURBS 基的临时投影适配面是未发布的普通 B 样条，仅保留计算所需的原系数、节点和域。
实际目标面的旋转面精度属性不能复制为该普通 B 样条的有效策略：投影前核验原策略，以及临时
COPY 属性的独立、唯一、单用户身份，再仅从临时面移除它。原面的属性、精度和所有权保持。
这不向普通 B 样条授予目标精度，也不调整投影精度或物理验收预算；最终同参数复核仍使用实际目标面。

原生 COPY 属性保留精度的 binary64 值。接缝分类产生的真实 owned `SmCrvOnSurf` 副本，
须通过支撑／UV／生成线的所有权与 context 核验后才能继承同一几何分辨率；假 backlink
或借用标志不构成拥有关系。原生文件中的完整目标面仍走已有曲面属性通道。
旧 COS 内嵌几何编码不能保存其支撑的任意属性，因此单独导出含这项内嵌精度的派生曲线会
明确拒绝，写入失败向上传播，不以丢失精度的数据冒充成功。如果完整模型的必需定义包含
该未支持结构，整个存档失败，不删掉定义后继续。分类时的临时接缝不作为模型定义写出。
带此策略的旋转面转为普通 NURBS 表示，以及需要该转换的非均匀 BRep 变换，目前在修改前拒绝；
建模副本的其他失败仍遵守内核现有非事务性合同，不承诺通用回滚。

公开 CLI 合同见
[`test_target_surface_precision.py`](../../tools/step_import_native_validation/tests/test_target_surface_precision.py)，
使用公开近极点旋转面控制，不读取私有模型库；模型级的数值／原生资格仍由相应 native 合同建立。

## 显式终段 NURBS 参数域延拓（开发解释）

`Options::terminalDomainInterpretation` 只在显式通用路径启用，绑定不可变原件 SHA256、
曲面实体、其实际 pcurve 以及原始参数数字区间。未提供该选项时，原参数域检查与结果保持不变。
这是假定源有效域之外采用原终段有理多项式的开发解释，不是源定义规定的域外几何，
不作为严格原件导入通过或原域之外的零位移修复。

首个范围为夹持、内部节点多重度不超过次数的连续样条：次数 1—17 的正权
`B_SPLINE_SURFACE_WITH_KNOTS`，及相同条件 B 样条生成线的 `SURFACE_OF_REVOLUTION`。
生成线／样条曲面的源十进制控制点、权、节点和精确长度比参与代数运算；
齐次 Boehm 插节点与终段 Bernstein 多项式延拓保留原有效域公式及源参数身份。
旋转面的 U 仍为已绑定 SI 角单位，V 为生成线参数；首版不延拓旋转 U。
源字节、源 UV、拓扑、角色和单位均不改写，不拟合定义几何，不启用域外求值或钳制作为替代。

目标二进制区间向外包住显式请求区间。证明读取构造及角度图调整之后实际存储的齐次网，
针对整个新计算域与精确源参考作共同节点细分，使用 Bernstein 交叉分子上界和正权分母下界，
不把有限采样或仅原域内的限制证明当成新域误差界。曲面直接使用一份 `quality.definitionMm`。
旋转面生成线使用其中一半，另一半约束源轴精确归一化、实际存储框架、原点转换在完整
新生成线正权控制包络上的误差；框架系数矩阵界覆盖全部旋转角。
两部分合计仍须满足同一份定义预算。求值器/libm 的全部舍入、UV 对应、拓扑及建模资格
不由这项定义证书单独建立，仍受各自检查约束。

调用者必须提供非零曲面数、证明控制槽与累计工作预算；当前上限分别为源记录容量、
2,000,000 与 100,000,000。整数中间量和文本长度另有固定容量界。
负延拓权、范围／原件绑定失败、未命中的计划、未实际构造的指定 pcurve、数值证明未建立、
容量耗尽和取消均拒绝发布，保留其区别。与修复、定义筛选、源错误隔离、周期拓扑归一化或
支撑域限制的组合尚未验证，配置阶段拒绝。

`ModelSnapshot::TerminalDomainInterpretation()` 返回 owning 只读请求收据；报告根记录一次
完整计划、动作、原参数域阻断诊断、实际新域、整体误差界与累计工作，嵌套报告引用该根。
所有计划完成且普通导入检查、必要报告与最终提交成功后，返回 `AcceptedUnderInterpretation`。
失败与取消释放未发布候选；原生存档和独立建模副本不继承 STEP 导入资格。

CLI 可显式传递 `--terminal-domain-source-sha256`、
`--terminal-domain-surface ID:UMIN:UMAX:VMIN:VMAX`（未扩展的轴用 `-:-`）、
`--terminal-domain-pcurve SURFACE:PCURVE`，以及 `--max-terminal-domain-surfaces`、
`--max-terminal-domain-proof-controls`、`--max-terminal-domain-proof-work`。
这些参数不按文件内容推断，也不在默认导入失败后自动重试。

公开合同测试见 `tests/StepImportTerminalSplineTests.cpp`、
`tests/StepImportTerminalRequestTests.cpp` 和 `tests/StepImportTerminalDomainTests.cpp`：
解析盒体、轴对齐及倾斜圆柱对照默认拒绝与显式开发解释，核对原字节、独立面积／体积、
模型复制、原生存档回读、共享定义的两重复实例装配，以及取消／资源／必要报告的发布边界。
这些测试建立其公开样件的范围，不承诺任意样条、完整 AP 一致性或生产模型库通过。


### 未标记外环的非闭合 B 样条区域

通用开发路径在源 `u_closed`、`v_closed`、`self_intersect` 均明确为 `F` 时，
可对多项式及正权有理 B 样条面执行已安装 UV 的曲线相交／包含分类。
这些源声明是范围限制，不是连续单射或无自交证明。原生属性还必须确认两个方向均不闭合、
没有精确／近似极点、缺失极点、越极点或未配对无面积环；闭合图或未知声明继续 Deferred。
非闭合面不执行周期缝分类，其未初始化的周期枚举不冒充已通过的周期检查。

必须得到唯一外环、合法内环及方向，没有坏嵌套、无面积或三维／指针闭合问题。
包含关系来自内核曲线分类，不以源 SET 次序或初始包络选定最终外环。
只通过完整所有权接口调整目标环次序，源 `FACE_BOUND`、几何、UV、单位与形状角色不改写。
报告以 `NativeSplineCurveIntersectionContainment` 标明派生外环身份；原工作容差和提升误差门槛不变。
普通曲面检查、最终 UV、原生有效性、必要报告与原子提交仍全部执行。

### 旋转面的受控派生 UV 与区域

旋转面纳入圆柱、圆锥和 B 样条已有的单次受控投影路径，求解目标为派生 UV 验收预算的
八分之一。投影器的距离／近似统计可涉及另一曲线参数，不能代替源三维边与提升 UV 在
同一原始 t 上的比较。只接纳单分支，继续对实际原曲面执行节点跨度配对量测、原生有效性、
工作容差和完整发布检查。原始 NURBS 基模式逐控制点、权、节点和域比较临时普通支撑面；
它不是拟合或替换定义几何。所有源表示、源 t、UV、单位和预算保留。

未标记外环的旋转面当前仅接纳原生 U 单周期、V 不闭合且无精确／近似极点的图，
