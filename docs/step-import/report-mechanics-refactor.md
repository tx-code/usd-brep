## module 与 seam

源层内部报告 module 负责唯一的字节预算、JSON字节转义、事务性交付与来源位置。
02、03、04是三个实际 adapter，各自保留字段、类型、单位和有理数等领域序列化。
现有 `InspectJson` interface 是验收 seam；不通过测试私有 writer 证明正确性。
上游报告直接写入同一受限缓冲区，不再先生成独立的完整 JSON 字符串。
这使预算与位置策略具有 locality，也让三阶段共同获得同一修复的 leverage；
删除共享 module 会把这些机制重新复制到三个 adapter，符合 depth 的目标。

## 行为合同

- 公共函数、CLI选项、退出码、报告版本、字段顺序、转义方式、嵌套换行和最终LF保持。
- `report_bytes` 计算最终输出的全部字节，包括嵌套对象和换行。恰好N字节可交付，
  N−1及零预算失败并清空旧输出；不得交付部分JSON。
- 已完成捕获时，即使语法、索引或引用检查失败，诊断仍具有一基行号和字节列号。
  未完成捕获时位置为null；完整空输入的EOF为(1,1)。CR、LF分别换行，CRLF整体
  视为一次换行，下一行起点位于LF之后。位置解析与源快照索引保持一致。
- 唯一预期的真实样件输出变化是04上游失败诊断从null恢复为已有捕获字节的位置。
  01样件、独立真值、03/04规则见证和原完整规格不改。
- C++17继续作为基线，并验证C++20。不得引入OCCT/STEPcode读取依赖。
- 新证据包声明新的依赖清单版本；既有包按既有清单复核，历史记录不重写。
