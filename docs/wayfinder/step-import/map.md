## Destination

形成一份足以交付实现的设计规格：自有 C++ STEP loader 将支持范围内的精确几何、拓扑与基本装配转换成可供精确查询和后续建模使用的 SMLib 模型；定义严格失败行为、受限修复预算与可重复验收。地图完成时，进入实现前的重要取舍均已解决并由用户确认。

## Notes

已由用户确认的本轮约束：先设计后编码；支持 AP203/AP214/AP242 的共同精确 BRep 子集；保留基本装配层级、重复实例及各自变换，区分开放壳与闭合实体；默认严格导入，修复在副本上按预算执行，超预算拒绝；产品导入链路不依赖 OCCT，测试允许独立读取器交叉检查；解析合成案例作为主要正确性参照，任何单一内核都不作唯一裁判。

完整 PMI/GD&T、整个 AP 的所有实体不属于已承诺范围。AP 标签识别不等于几何能力已支持。

每次会话先读 `wayfinder`、`grilling`、`domain-modeling`；源模型/拓扑审计用 `smlib-brep-model`，healer 内部问题用 `smlib-kernel-healing`，验证选择用 `usd-brep-test-selection`。研究票用 `research`。现有调查材料是证据输入，不等于本地图已经作出接口或算法决策。

既有材料：[实施建议草案](../../step-import-repair-plan.md)、[Truck 调查](../../truck-step-import-assessment.md)。本地模型库清单与真实文件名映射仅保存在本机，不进入公开源码。允许测试模型库，不代表允许发布其中模型。

研究记录本轮先保存在各自证据目录并由本地票链接；不为只读调查切换共享 checkout 的分支。需要修改原型代码时另开隔离工作区。此为本地 tracker 的研究上下文约定。

完整实施整合视图：[独立STEP导入与受限修复设计规格](../../step-import-repair-spec.md)。0.1版已由用户确认为后续设计基线，本地图已完成；用户明确暂不编码，设计确认不自动启动实现。

## Decisions so far

- [真实模型库要求哪些 STEP 表示与几何实体](tickets/01-corpus.md)：有限文本画像已给出实体候选及覆盖缺口；真实装配和周期奇异情况仍需专项夹具。
- [STEP 参数与拓扑如何无歧义地进入 SMLib](tickets/02-kernel-contract.md)：源语义必须独立保留，目标构建存在参数转换、输入改写和验证副作用，需由隔离适配器封装并验收。
- [loader 的模块边界和中立数据模型是什么](tickets/03-module-boundary.md)：采用原始文档、中立模型、SMLib 适配器三个模块；中立接口先内部化，允许经验证并完整记录的等价表示规范化。
- [哪些文件和实体能够被严格接受](tickets/04-parse-completeness.md)：首版自包含 Part 21 常用精确 BRep；所选请求全成全败，未知内容按影响分类，必需或影响不明的内容不支持即拒绝。
- [单位坐标与装配实例的正确性契约是什么](tickets/05-context-assembly.md)：规范单位 mm/rad，缺必需单位拒绝；保留 local 零件定义与实例变换，首版支持刚性、均匀缩放和镜像。
- [精确 BRep 构建和参数边界怎样验收](tickets/06-exact-brep.md)：尊重源优先表示、冲突拒绝；定义几何保真，派生UV可受控近似，周期/奇异语义保留并在候选验收后发布。
- [允许修复哪些缺陷以及怎样限制模型变化](tickets/07-repair-budget.md)：局部白名单、显式质量配置、局部/累计保护与分阶段tol对账；预算参数化，生产默认数值延后。
- [怎样用合成参照和真实模型判定导入正确](tickets/08-validation-corpus.md)：四层分批验收和代表性查询/建模资格，零已知错接纳/丢内容/超预算/部分发布，证据不足不晋升。
- [现有容差系统与 OCCT 的差距怎样影响修复预算](tickets/12-tolerance-contract.md)：SMLib已有实体容差与传播；新loader缺少已验证的源精度到预算契约，1 μm/5 μm候选尚未批准。
- [哪条 SMLib 构建路径能满足保真和失败清理要求](tickets/11-builder-feasibility.md)：受控构建已有共享/空腔/周期承载证据；需单次候选、UV/区域/tol独立验收，任意失败的进程内完整清理未获证明。
- [调用者怎样得到模型诊断和可追踪的修复结果](tickets/09-public-result.md)：owning只读快照与独立建模副本，核心库/应用隔离分层；取消/成功统一裁决，工作区版本匹配时自动接入。
- [规格是否足以进入分阶段实现](tickets/10-spec-ready.md)：规格0.1及P0—P7验收门槛已获最终确认，设计完成；暂不编码，未证能力按阶段验证后晋升。

## Not yet specified

本版设计收束所需的重要取舍已确认。实现期能力验证及其门槛见[完整规格](../../step-import-repair-spec.md)；未证实现不因地图关闭成为已支持能力。

## Out of scope

- 本轮实现 loader、交付生产级 STEP 读取器或改写 healer；当前终点是设计规格。
- 网格化算法修复，以及以显示成功作为精确模型正确性的证明。
- OCCT 作为产品读取/转换后端；OCCT 文档、源码阅读及测试侧对照可用。
- 修改现有 USD 体系、完整 STEP 写出、PMI/GD&T 编辑、非 STEP 格式导入。
- 将私有模型库、客户模型、MW SDK 或许可证发布到公开仓库。
- 创建远端 issue、PR 或推送本地图。
- 实现/真实失败之后提出的新增实体范围、GUI呈现细节及超出现有白名单的新修复方案另立后续努力；当前规格保留其扩展和能力晋升规则。
