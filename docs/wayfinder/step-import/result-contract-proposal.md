# 导入结果、诊断、模型所有权与发布契约建议

状态：2026-10-15 已讨论并获确认的设计资产。用户已确认只读快照与独立建模副本、核心库与应用隔离分层、取消/成功统一裁决及匹配版本自动接入；正式决策以对应票为准。类型/函数名称、ABI和实现细节仍为示意，没有增加稳定接口或绑定，也不代表实现已验收。

对应票：[调用者怎样得到模型诊断和可追踪的修复结果](tickets/09-public-result.md)。事实输入：[构建路径与清理实测](builder-feasibility-assessment.md)。

## 建议的调用面

首版先形成内部可测试的C++接口；成熟后再经SM_API的opaque handle和Python owning wrapper暴露。下面是语义示意，不冻结函数名、类型名、ABI或字段布局：

```text
inspect_step(input, resource_limits) -> source_snapshot? + inspection_report
import_step(input_or_source_snapshot, request, cancel_token) -> ImportOutcome

ImportRequest = selected_roots + quality_configuration
              + optional_explicit_repair_plan + resource_limits

ImportOutcome = terminal_status + model? + source_snapshot? + report
```

默认不提供修复计划。需要修复时显式给白名单/预算，仍从同一不可变源快照开始新候选。已确认的全请求全成全败不变，不增加自动部分成功或自动放宽的开关。已有模型不是隐式out参数；函数不主动改应用工作区。

inspect只供检查源内容、支持范围、单位、错误和修复准入；不返回可建模目标，不能把它称作精度合格导入。import必须显式选择质量配置，最低要求与请求的额外下游资格全部满足才返回Accepted。

## 返回状态与模型的关系

| 终态 | 模型 | 含义 |
|---|---|---|
| Accepted | 必有完整owning导入快照 | 所选请求完整满足本次声明的验收；可有已解释的元数据/uncertainty警告，不能残留必需检查失败或无法判定 |
| Rejected | 无 | 已证源非法/不一致、必需能力未支持、超质量或修复预算、证据不足、声明的资源限制等；附可定位原因 |
| Cancelled | 无 | 用户取消在成功提交前赢得裁决；候选撤销，尚未完成撤销时不能提前宣称该终态 |
| Failed | 无 | 内部错误、worker崩溃、异常资源故障等，不能据此指控源模型非法；报告可能不完整 |

Rejected/Failed的具体reason code必须区分IO、解析、引用、单位、范围不支持、构建、验收、预算、资源/截止时间与基础设施。超时是DeadlineExceeded，不伪装用户取消；失联且原因未知时记录未知，不猜成崩溃或取消。

能力资格按操作及适用范围单独记录，例如精确求值/查询、截面、代表性切割/裁剪。每项区分Qualified、NotQualified、NotChecked与Indeterminate，绑定质量配置/版本/证据。Accepted不表示任意参数下的所有建模操作都可靠。调用方要求的资格未满足，则整个请求不以Accepted交付；非必需的未测试资格明确列出。

报告的“通过”是相应检查在其范围内通过，不能将采样证据改写为全域上界证明，也不能把未运行写成0误差。

## 模型所有权

建议成功返回只读的ImportedModel快照：

- 有自己的结果/修订身份，持有零件定义、装配occurrence、变换、开放/闭合及空腔类型，以及来源对应关系。
- 查询侧保持模型定义不可变；内核可能产生派生缓存，因此“只读”不表示可以并发调用native查询，也不表示未经审计就允许改变有效tol。
- 已发布快照的验收基线不原地改写。可能改定义/有效tol或尚未证明只读的检查在临时副本执行；快照只开放已验证的查询。只读视图也不能悄悄泄出可变native句柄。
- 拥有所有native根与context的内部owner，禁止借用job/staging的生命周期。对象先销毁，context最后销毁；不能把context当arena。
- 返回给调用者的definition/occurrence/face/edge等视图须持有owner或等价生命期租约。导入函数返回、job对象释放、父结果变量释放后，仍在用的有效视图不悬空；最后一个owner引用释放后才清理全部对象。
- 这属于新导入接口的目标，不能宣称现有_omni_solid裸指针/borrowed wrapper已具备这些保证；需要独立绑定和释放测试后才稳定化。
- native对象指针、当前拓扑遍历下标、worker PID均不充当持久来源ID。

后续建模通过显式materialize/copy操作得到一个独立可编辑BRep；可指定零件定义或occurrence。occurrence版本应用已确认的变换与方向、质量验证，并拥有自己的context/几何。该操作另有成功/失败结果，不修改导入快照或其他共享实例；也不在读取快照时悄悄复制整个装配。

只允许已验证的本进程materialization暴露给现有SmApi/_omni_solid。跨进程模型不能凭一个数值句柄当成SmBrep*或现有Python Brep；其传输、重建、有效tol/来源保持和重验必须另行证明。

## 源快照与失败后的修复

只读源快照是对本次实际输入字节与已解释语义的保留句柄，不是失败SmBrep或staging。原始文档/中立布局继续内部化。

在输入已完整捕获并满足资源策略时，Accepted、Rejected、Cancelled/Failed都可以携带源快照，供定位、导出证据和显式重试。IO/输入捕获未完成时可以没有源快照，报告说明可用范围，不能拿文件路径冒充已冻结源。

源快照按配置拥有输入缓冲或不可变本机暂存，绑定内容hash；保留的文件不得被原路径外部改写影响。保留超过内存/磁盘/生命期限制时明确拒绝或要求调用方重新提供相同hash输入，不静默丢失后仍允许重试。报告本身不强行持有整个大型源文件；可保存必要SourceRef/摘录，并注明完整源是否仍可访问。

严格导入失败也可以显式申请受限修复：从源快照重新解释/复制可修复的中立数据、另建候选。它不要求先有一个合格BRep，也不允许复用失败暂存图。无法解析、缺必需依赖/单位或修复不在已验证白名单时明确拒绝；“可申请修复”不保证修复成功。

对已有合格导入结果发起修复时，旧快照由原owner保留。修复失败不返回新模型，也不把旧模型塞进此次失败结果伪称修复成功；调用者仍能继续使用先前持有的旧快照。

## 诊断与变更报告

建议一个可独立保存、版本化的ImportReport，包含三类明细，避免把所有变化都叫修复：

| 明细 | 必需内容 |
|---|---|
| Diagnostics | 稳定code、严重度、阶段、归属范围、因果关系、源定位、测量值/单位/阈值与证据强度；人类文字供显示，不能靠解析报错字符串控制流程 |
| NormalizationReport | 单位/坐标/参数转换、目标必要的seam/拆分等已验证等价规范化及派生UV构建；源→目标多对多映射、证明/验收证据 |
| RepairReport | 每个尝试动作及Applied/Verified/Rejected/RolledBack等状态、不可变基线、改前/后身份、实测缺口/位移、逐实体tol和传播、累计/中间峰值、预算及局部保护、最终候选是否被接纳 |

SourceRef包含文档内容身份、源实体/记录ID、文件位置；可用时加所选根、零件定义、occurrence路径、edge-use/pcurve等上下文。找不到精确定位时表达未知和已知上下文，不编造源ID。重复实例的同源几何与不同使用身份分别表达。

完整报告还绑定request ID、输入hash、选择范围、质量配置完整快照/版本、修复计划、实际构建器与运行库版本、结果修订、各检查状态和适用范围。不把日志摘要代替必需内容完整性账本。

修复只改tol而未减小gap时报告ToleranceAdjusted；没有修改或仅做等价规范化时报告NoRepairChange。失败时允许记录已尝试但撤销的变化，不能称已发布修复。未知测量值用Unavailable/Indeterminate，不填0。

worker中断时，父侧保留已确认收到的诊断、最后完成阶段和退出证据；report.completeness=Partial，说明缺失项。允许按预算截断调试日志，但必需验收证据不足必须影响接受判断，不能截掉错误后返回Accepted。

同步核心发生不可恢复崩溃时无法返回ImportOutcome；极端内存不足时也不能承诺完整分配报告。隔离封装须把worker终止转为最小失败记录，明确没有完整报告；本进程模式保留其受限的故障保证，不能用上面的逻辑返回类型掩盖这一点。

报告可复制/导出为带schema_version的数据；不依赖native对象指针或仍存活的模型。稳定的诊断code和版本兼容政策在接口落地时明确，首版不冻结原始STEP/中立模型的公开序列化格式。

## 执行与隔离建议

建议分清两层，首版不为了导入改造整个建模接口：

1. **C++核心调用**：同步、本进程返回owning模型，支持合作取消；宿主可将它放在后台执行，但同一进程的native调用须遵守已知串行限制。专属context不证明线程安全，也不承诺捕获进程崩溃或内存损坏后还能继续使用进程。
2. **应用任务封装**：GUI/批量任务需要硬取消、硬超时或故障隔离时，把完整候选任务放进独立worker。源快照/报告/模型句柄明确所属进程；同一worker一次一个native调用，并行通过多进程。

worker结果有两条物理交付途径，不能混淆：

- 候选worker保留目标模型，成功后将worker/session及模型句柄的owner交给结果；job结束不销毁已交接的模型。调用在所属进程执行，应用使用代理，这不是现有本地Brep。
- 传回经过验证的精确模型数据，再在目标进程重建/重验。该链路目前未证明，不能当作现成能力；也不能通过USD单tol或重新执行未隔离构建来声称同等保真/故障隔离。

首个应用隔离探针建议优先前一种，避免先创造未经证明的跨进程BRep格式。但这需要最小模型查询/生命周期代理；它是待实现/验收条件，不是现有GUI已经支持。

新导入或修复候选worker必须与已发布模型owner隔开。禁止把承载旧快照的worker用于可强制终止的新候选任务，否则“取消不影响旧模型”不成立。成功的候选worker可以被结果owner接管；在最后一个模型/视图引用释放后，任务管理器再回收它。

本进程核心的native崩溃会影响宿主，不能给它套上隔离层的保证；隔离进程退出也不能代替父侧句柄、临时文件、部分报告和任务状态清理。这些均需对应故障验收。

## 取消与成功的唯一裁决点

取消接口表达“请求取消”，不等于“已完成取消”。在受控阶段边界检查；正在运行的不可中断native调用允许继续至安全返回，随后丢弃候选。不给出未验证的立即响应时限，不使用强杀线程或在调用中途销毁context。

成功需完成源完整性、目标构建与独立验收、有效tol/修复预算对账、报告必要部分固定，以及模型owner的可靠交接。只有到此才尝试一次性提交终态。

| 竞争情形 | 结果 |
|---|---|
| 取消先于成功提交赢得裁决 | 阻止Accepted，候选撤销/回收后返回Cancelled；不能稍后把迟到worker成功发布 |
| 成功提交先赢 | 已返回Accepted与owning模型；后到取消为TooLate/AlreadyCompleted，不撤销模型 |
| 原生调用尚未安全返回 | 仍为取消处理中；隔离模式可在约定宽限后结束候选worker，等待回收；本进程模式不假装能立即停止 |
| worker崩溃或异常失联 | Failed并记录已知原因/不完整报告；没有确认的取消终态不能伪记Cancelled |

用户取消、超时和故障相遇时，由任务协调者一次性确定终态和原因，保留其他已观察事件；不得在两个回调中分别发成功和取消。重新尝试是新request ID/新候选，保留关联但不复用旧终态。

## 导入结果与应用工作区的两次动作

核心成功交付模型是第一件事，应用将其设为当前模型是第二件事。核心没有权力自动覆盖工作区；应用可以按已有交互自动应用，无需为每次成功新增人类确认。

应用提交使用expected workspace/document revision和request generation/token作原子比较，连同模型owner与关联report一起切换。

- revision/token仍匹配：一次切换完整请求结果；订阅者只能看到旧完整状态或新完整状态。
- 用户已编辑、切换文档、取消应用或新任务已替代：不覆盖新状态；保留导入成功但未应用的结果，应用层报告Conflict/Superseded等。
- 库内Accepted但应用失败：分别报告，不能改写导入事实或称导入失败，更不能丢掉caller仍持有的成功模型。
- 库内成功后撤销应用意图：阻止尚未发生的工作区切换；不把成功导入终态改成Cancelled。已切换的模型若需恢复，由应用的撤销/显式操作处理，不伪装取消回滚。

这里的原子发布是已确认的所选请求边界，不等于跨任意进程/文件系统的分布式事务。跨进程owner交接、提交确认丢失和重复消息须以幂等结果身份处理；在无法确认交接时，不把猜测的成功交给调用方。

## 进入实现前的验收义务

需要测试报告独立存活、结果/视图释放顺序、源捕获及预算、两个同时到达的取消/成功事件、候选owner交接失败、旧任务覆盖保护、worker普通返回/崩溃/硬终止后的父侧回收，以及失败源快照的修复重试。不能把上轮人工FailFast探针当作这些生产协议已经通过。

后续已确认的[完整规格](../../step-import-repair-spec.md)选定受控top-down作为首个平面/盒体纵向切片，MakeTopologyFromData保留内部候选；具体周期/奇异/NURBS资格按构建研究限制晋升。公共承诺依赖契约与验收，不暴露或锁定调用者选择构建器。
