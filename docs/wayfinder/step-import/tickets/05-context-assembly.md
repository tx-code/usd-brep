## Question

内部长度/角度规范、文件上下文单位、uncertainty 与应用容差如何区分？混合单位、嵌套变换、重复实例、镜像/缩放和外部引用怎样处理？哪些基本装配路径属于首版，失败影响整个装配还是单个根？

## Resolution comments

2026-10-15 · 用户确认以下三项政策。

### 单位与精度

规范长度使用毫米、物理角度使用弧度；按 representation context 解释源单位，保留原值、源单位与转换因子。必需单位缺失、矛盾或无法解释时默认拒绝，不猜测毫米。源 uncertainty、内核工作容差、导入验收阈值和修复预算分别记录，不用源 uncertainty 自动扩大允许的修复范围。

物理单位转换不等于对所有 knot、曲线参数和 UV 数值统一缩放。各几何类型的 source→canonical→SMLib 参数规则仍由精确 BRep 票确定；用户确认毫米/弧度不代表批准某个尚未验证的映射算法。

### 坐标与装配实例

零件几何保留在本地坐标，保留装配层级和 occurrence 的各自变换，重复实例共享零件定义。建模时按需生成 occurrence 的独立 BRep，不在导入时默认把所有实例展开成 world 坐标独立实体，也不通过改变共享定义影响其他实例。

源位置和实例身份必须可追踪；不为显示方便隐式重定向或重定位整个装配。多个上下文单位、嵌套变换和方向需组合验证，不能重复进行单位缩放。具体装配表示路径、源派生轴规则及多路径对账按规格细化，不因 HEADER/实体名识别就宣称通过。

### 首版变换范围

首版目标支持平移、旋转、均匀有效缩放及镜像，须验证方向、实体内外与长度型精度随空间尺度的变化。非均匀缩放、剪切延后并明确拒绝；外部文件引用沿用既定延后范围。零尺度、奇异或非有限变换不能以单位矩阵替代。

### 仍待后续决定

容差与修复预算的具体数值、源 uncertainty 缺失时的验收阈值、数值范围与资源限制、镜像/缩放 materialization 的实现、公共结果接口和实例建模操作不在本票提前批准。当前没有 end-to-end 导入或镜像/缩放动态验证通过的声明。
