# 精确 BRep 构建、参数边界与失败清理建议

状态：2026-10-15 讨论材料；源优先表示/冲突政策与受控派生UV近似已由用户确认，既定规范化及严格导入原则的应用记录在对应决策票。具体构建入口、算法和预算仍待后续证据。没有实现 importer 或修复内核。

对应票：[精确 BRep 构建和参数边界怎样验收](tickets/06-exact-brep.md)。

## 精确性的含义

保持已接受源模型的定义性几何、区域边界、邻接、方向和实例意义。采用已定义的数值验收阈值，不要求不可能的浮点逐位等同，也不允许把自由曲面拟合误差藏在“精确 BRep”标签下面。

优先保留原解析/有理 B 样条表示；允许经过验证的精确重参数化、节点插入或目标拓扑规范化。源几何必须通过近似拟合才可放入目标内核时，严格路径明确报未支持，不自动转网格或用另一个近似曲面替代。内核对某种 exact evaluator 的后续操作支持也需单独资格验证，不能仅以构造成功认定可建模。

## 三维边与源 pcurve 的处理

建议始终保存源 `curve_3d`、各 associated pcurve、所在面、使用方向和 `master_representation`。优先表示用于解释定义与数值处理，不能当作超阈值矛盾自动合法化的理由。

| 情况 | 建议行为 |
|---|---|
| 3D 与源 pcurve 经正确参数映射后一致，均可支持 | 按源优先表示建立定义，保留其他表示作一致性证据，转换到目标参数 |
| 数据有差异，但在既定验收阈值内、端点/方向/区域/周期分支一致 | 记录测量误差与判断条件，允许继续；不改变验收阈值掩盖偏差 |
| 源优先 3D，目标需要 UV 而源允许不提供该派生数据 | 在独立派生数据预算内构造目标 trim，记录来源及重建行为，验收后使用 |
| 源优先 pcurve | 保留 pcurve+surface 定义，验证其三维 lift；不能直接改为相信源3D曲线或重新drop。目标无法保持定义则未支持 |
| 源3D与源pcurve超阈值矛盾 | 严格导入失败，保留双方证据与来源；可以作为后续显式修复输入，不能默认选一条覆盖另一条 |
| 源优先表示不支持、周期分支不能确定、投影/验证不能得出可靠结论 | 明确未支持/无法判定，不交付成功模型；不能用最近端点或“较短那段”猜测 |

一致性检查不能把两个曲线相同的数值参数直接配对：需区分3D曲线参数、源pcurve自身参数、源surface UV与目标UV映射。核对端点、方向、边区间覆盖、边面贴合、source→target求值和使用语义。检查计划应覆盖内部段及方向/分支变化，端点或少量固定样点通过不足以当作严格几何证明；具体自适应/界估计方案在验收票确定。

## 目标 UV trim 的近似政策

建议允许**仅派生数据**采用有明确三维误差上限及分支/区域验证的近似，单独报告为 `DerivedApproximation` 类别，具体类型名留给结果接口票。

条件：

1. 定义性3D几何、原始pcurve及其优先语义保留，未被拟合结果替换。
2. 误差在三维物理空间检查，不能用统一UV数值容差代替；不能借此扩大定义几何验收阈值。
3. 环闭合、孔岛关系、边方向、周期侧别和区域覆盖保持。三维lift一致并不自动证明UV区域正确。
4. 近似预算与修复位移、容差增长预算分开；若UV缓存参与目标算法，误差须计入最终消费操作的有效质量契约。
5. 无法满足预算、没有足够验证证据或目标消费算法对该近似不可靠时，明确拒绝/未支持。

这里允许的是目标参数缓存的受控近似，不是给定义性曲线/曲面拟合开后门。对于源pcurve优先的数据，尤其要先证明目标仍使用等价定义，而不是把定义悄悄降格为可丢弃缓存。

## 周期缝与拓扑身份

- 同一个源 edge 只有一份逻辑共享身份，每个 face 内的 occurrence 单独保留。一个edge在同一周期face出现两次时，两个使用及两个pcurve分支都保留，不能按 `(face,edge)` 去重。
- 明确周期、展开区间和分支，不把所有UV压到主值域后丢失绕行次数；闭合点的3D重合不能消除其参数区别。
- 方向从 source edge/使用/bound/face/壳以及source→target参数映射逐层推导，不使用文件顺序或单个布尔值替代。
- 在已批准的表示规范化政策下，可以增加目标所需的seam、拆面或拆边；必须保持形状与源使用语义，记录source→target多对多映射、派生实体和理由。不能因某种源拓扑在SMLib不常见就把它称作源错误。
- 核对边界与区域覆盖，不能只凭壳/面/边总数相同或AssertValid通过认定导入正确。开放壳也必须保持开放，不自动封口。

## 闭合边、退化边与极点

| 情况 | 建议 |
|---|---|
| 端点同一顶点、曲线弧长非零的闭合边 | 合法闭合边；尽可能保留，不因端点重合就删除或无条件拆开 |
| 很短但非零的小边 | 保留并按实际几何检查；删除/合并属于修复，不用统一长度阈值当作“零边” |
| 三维塌缩但UV有非零行程的奇异边界 | 保留源UV行程、使用与极点语义；选择已验证的目标vertex-loop/seam/分面等表示，不伪造微小三维线或将其直接跳过 |
| 合法 source vertex_loop | 显式映射其顶点及使用；目标outer/inner限制可能不同，需目标规范化及验证，不能硬塞进普通edge |
| 目标尚无可靠表示的奇异情况 | 明确未支持，并保留源证据；不能continue后报完整成功 |

SMLib 的闭合边有合法表示，`SmBrepData` 的极点 type 3 又有被跳过的路径；不能把任一入口存在当作所有退化情况可无损构建的证明。

## 构建、发布与失败清理

目标保证是：一次请求使用一次性的候选对象与明确所有权，全部验收通过后才发布；任一失败不交付本次候选模型，保持原始文档、中立输入和已发布模型不受这次构建改变。

1. 构建前完成索引、引用、类型、方向、几何域及所有权计划检查，避免把未可信序列化数据直接拼成指针图再交给AssertValid。
2. 中立模型只读；目标几何、staging data和运行时对象分配/复制到适配器管理的生命周期中，不借用源模型的可变内核对象。
3. 每次资源移交都明确拥有者。对象必须在其context失效前销毁；失败依赖RAII/明确移交协议，不依赖手工清除一批难以确定归属的指针。
4. 禁止隐式healing/stitch/删面/容差放宽；必须发生的表示或派生数据构建单独记录。调用前后对账，检测不可解释的face域裁剪、实体丢失和工作容差变化。
5. 部分失败的staging或目标图不重试复用；新尝试从不可变输入重新创建。调用状态、内部诊断和独立验收分别收集。
6. 普通失败清理、分配失败和取消路径须以故障注入及活跃分配对账验证；候选隔离不等于进程崩溃也能原子回滚。native崩溃/内存损坏需要隔离worker或拒绝使用该不可靠调用路径，不能靠C++catch宣称已恢复。

当前不直接拍板 `MakeTopologyFromData` 或 top-down constructor 哪一个作为唯一实现。既有研究已见其自动行为、输入改写和UV放置约定风险。应把二者放在同一个可丢弃adapter探针中，验证关闭隐式修复、反向use+authored pcurve、open shell、共享边、solid+void、极点以及失败清理后再决定。不能把“现有API成功”升级成目标保证。

## 接受前的五项检查

1. **来源完整**：所有必需依赖和所选根均有对应，unsupported/invalid未被过滤；新增或拆分目标对象可对账。
2. **图和方向正确**：先确定目标图可安全遍历，再验证mate/radial/环连接、源方向、孔/外环、开放/闭合及空腔语义。不能简单要求源shell数量等于target runtime shell数量。
3. **定义几何一致**：单位、参数区间、源→规范→target的点/导数/法向、顶点端点、边面贴合及使用方向有独立证据。
4. **区域与派生数据正确**：pcurve映射、闭合、周期分支、极点行程和面覆盖符合源语义，近似预算分别记录。
5. **目标可消费**：完成 `ValidatePointers` 和一次 `AssertValid(SM_LEVEL_2,SM_WALK)` 并保存报告及前后状态；代表性夹具再做精确查询与一项选定的下游几何操作。具体操作和参照在验收票选择，不能据此承诺所有建模操作永远成功。

内核检查可能改变缓存和容差状态，需记录变化；源模型的检查证据不得仅从相同目标算法生成。后续操作失败时区分转换缺陷与已有内核限制，不能自动改判源文件坏。结果至少区分源非法、不支持、构建失败、验收未通过和无法判定。

## 最小正负例矩阵

| 类别 | 正例 | 反例/失败路径 |
|---|---|---|
| 3D/pcurve | 相同几何但不同参数/方向；3D和pcurve各为优先表示 | 超阈值冲突、不支持master、内部段偏离但端点吻合 |
| 周期 | 圆柱双侧seam、跨周期孔、缝上重复occurrence、球/环面绕行 | 把两侧UV并成一条、主值归约导致区域取补集 |
| 奇异 | 闭合圆、球极点、圆锥顶点、合法vertex-loop | 删除非零闭合边、伪造微小线、type3静默丢失 |
| 方向/区域 | 正反向edge/use/bound/face组合，镜像非对称实体，空腔 | 环排序错误、反向use上UV放置不当、空腔被当实心 |
| 生命周期 | 重复成功/失败无活跃分配漂移，输入不变 | 分配点失败、取消、partial graph、目标API已改输入再失败 |

这些是设计验证要求，不是已运行通过的案例。

## 本轮讨论结果

1. 尊重源优先表示，并验证各表示的一致性；超阈值源冲突严格失败，默认不选择3D或pcurve强行覆盖。
2. 定义性几何不做静默拟合；允许单独预算、可验证且保留源语义的目标派生UV数据近似。
3. 周期/奇异情况按已批准的等价表示规范化政策处理，无法可靠表示就明确未支持；一次性候选构建和验收后发布作为adapter接口保证，具体入口由探针选择。

前两项已由用户明确确认；第三项为既定严格导入与表示规范化原则的应用。接口保证必须在实现前通过构建路径研究及后续测试落实，不能当作现有内核保证。
