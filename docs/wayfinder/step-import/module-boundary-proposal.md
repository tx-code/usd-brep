# loader 模块划分建议

状态：2026-10-15 讨论材料；模块划分、内部中立接口及经验证记录的目标表示规范化已由用户确认。具体决策以对应决策票为准；本文件不表示实现已经存在。

对应决策票：[loader 的模块边界和中立数据模型是什么](tickets/03-module-boundary.md)。

## 建议

采用三个模块：原始 STEP 文档、中立导入模型、SMLib 构建适配器。类型化 STEP 访问作为原始文档的内部视图；检查和可选修复分别执行。三个模块各自承担一项完整职责，不要求为每一种实体建立独立的公开接口。

| 模块 | 持有的内容 | 允许的处理 | 必须保留的事实 |
|---|---|---|---|
| 原始 STEP 文档 | HEADER、所有 DATA 段、原始记录、实体 ID、引用、简单/复合实体组成、源位置；必要时保留数字/字符串原文 | 语法解析、索引、类型与引用检查、按需类型化访问 | 文件写了什么；未知实体也不能消失；不能因兼容或修复改写源记录 |
| 中立导入模型 | 已支持的精确几何描述、拓扑及每次使用、单位/参数语义、零件定义与实例、来源关系及诊断 | 解释源语义；按明示规则做单位/坐标/方向规范化；形成可独立检查的构建输入 | 源实体到中立对象的可追踪关系；共享身份、多个 pcurve/优先表示、周期分支、开放/闭合类型和已知不一致 |
| SMLib 构建适配器 | SMLib context、几何与拓扑对象、一次性 staging data、目标参数映射和构建账单 | 将中立输入转换到目标表示；封装构建入口副作用；验证后发布模型 | 中立输入不可被构建改写；目标新增/拆分/合并等表示动作可对账；失败不发布不完整模型 |

不把 `SmBrepData` 定义为中立模型：它属于目标适配器，可以作为内部装配工具。它的数据约定及构建行为并非 STEP 源语义的完整容器。

## 原始文档与类型化访问

原始文档是源证据。实体类型、字段语义和引用类型由按需视图解释，不再复制一份整文件级类型对象图。构造一个受支持形状前，必须走完该形状的必需依赖检查；按需访问不意味着漏查未知几何。

未知的样式等元数据可以原样保留，但其不影响形状的结论必须来自依赖/语义分类。未知实体落在几何、单位或装配的必需依赖路径上时，输出明确的不支持诊断。

大文件不应同时保留多份整文件文本、通用 AST 和相同字段的类型化副本。源字节存储方式、释放时机与内存硬预算留给资源设计，不在此预选 mmap 或全量载入。

## 中立模型的具体职责

这是受支持导入语义的数据模型，不是新的几何内核，也不是全部 STEP EXPRESS 模式的第二份拷贝。首版建议保持内部接口，在回归中验证契约，等真正出现第二个消费者后再决定公开和稳定化范围。

- **几何**：平面、解析曲线/曲面、B 样条等明确的参数描述；定义性参数与容差、来源和周期信息分开保存。
- **拓扑**：实体身份、边的端点/区间、环的有序使用、面相对曲面的方向、壳与实体关系。不能按坐标相同就合并源顶点。
- **边的使用**：同一共享边在两个面或同一周期面上多次出现，各保留自己的使用方向、所在面和 pcurve 分支。不能只按 `(face, edge)` 去重。
- **装配**：零件定义与 occurrence 分开；一份定义可以被多个实例引用，层级与各自变换保留。
- **单位与参数**：物理量转换采用明确约定，最终长度/角单位由后续票决定；不能把全部 knot、曲线参数和 UV 都当长度统一缩放。
- **来源**：每个中立对象保留源文档/实体关系；构建结果另有中立对象到目标对象的映射，可为多对多。模型已经分面或拆边后也应能定位原 STEP 定义。
- **冲突**：源 3D 曲线、多个 pcurve 和优先表示一起保存；中立层能表达“已读到但存在冲突”，该状态不代表可接受模型。

中立层不包含 `SmFace*`、`SmEdge*`、`SmContext*` 或 `TopoDS_*`。相关几何映射和对象生命期知识留在具体适配器中。

## SMLib 构建适配器的职责

输入为不可变的中立模型；输出包含模型、来源映射、转换动作和检查结果。成功输出的所有权与 context 生命周期必须由这个接口统一管理，不让上层调用者拼装 Euler 操作或管理半成品指针。

适配器负责源参数到 SMLib ordinary/STEP-style/NURBS 参数的换算，必要的方向奇偶处理，以及 `SmBrepData` 的一次性 staging、失败清理和副作用隔离。是否选择 `MakeTopologyFromData` 还是更细的 builder，仍待后续探针决定。

“隔离构建后验证再发布”是新接口的目标保证，不是当前内核调用已具备的性质。尤其不能通过关闭 healer 就推导整个构建过程原子、无副作用。

建议允许有据可验收的目标表示规范化，但必须单独分类、报告。可作为讨论例子：参数重排、精确的节点插入、目标所需的 mate 展开、必要的 seam/分面。它们是否保持源模型的形状和使用语义需要逐种证明；本票不提前批准所有动作。

## 检查与修复

检查分三个位置：源结构/引用检查，中立语义与几何一致性检查，目标图/几何及后续查询检查。任一层失败应带自己的阶段与来源，不能以最后一个成功句柄覆盖先前失败。

修复是在已定义的不一致上执行的显式操作，修改副本，并产生新的结果及变更报告。移点、改3D边、把不同源顶点合并、删小边、封口或提高容差均不能悄悄放在构建器里。具体授权操作和预算留给修复决策票。

派生 UV cache 的构造/近似也必须单独记录，不能当作源 pcurve 的无损替代；一旦源优先定义依赖 pcurve，不能以“目标 UV 是派生数据”为由丢弃它。

## 三个用来检查划分的场景

1. 源长度为米、曲面角参数需换算：原始层保留源值，中立层解释单位与参数类型，目标适配器负责 SMLib 的最终求值参数映射。错误不能变成 healer 在后面“修圆”。
2. 一颗螺栓有一百个实例：中立层一份零件定义加一百个 occurrence；实例变换不应改变共享原几何。目标实例策略可独立选择，不迫使源层重复解析。
3. 同一边的3D曲线与两个pcurve互相矛盾：三个模块都有自己的读入/构建结果，但不能因此发布成功。保留冲突来源，按后续优先表示政策拒绝或进入显式修复。

## 已提交讨论的架构取舍

1. 中立模型先作为内部、可测试接口，不承诺首版公开稳定格式。
2. 原始层只保留证据；中立层解释和规范化；SMLib 特有的参数/拓扑处理留在适配器。
3. 严格导入是否允许有验证依据、完整变更账单的目标表示规范化；与改变定义性几何的修复分开管理。
4. 来源与诊断贯穿各层；具体完整源文档保留时长、归档选项和内存预算在后续票决定。

前三项的架构原则已由用户确认并登记到决策票；具体允许的规范化动作及验证规则由后续票决定。第四项中的源文档保留时长、归档选项和内存预算仍未决。
