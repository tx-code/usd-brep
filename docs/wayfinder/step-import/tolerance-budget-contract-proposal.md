# 源精度、内核容差与修复预算的连接契约

状态：2026-10-15 讨论材料；显式质量配置和参数化预算、生产默认值延后已获用户确认，具体决策以修复票为准。1 μm/5 μm候选不采用。未实现相关代码或完成定标。

对应票：[允许修复哪些缺陷以及怎样限制模型变化](tickets/07-repair-budget.md)；事实依据：[SMLib与OCCT容差契约对照](tolerance-system-assessment.md)。

## 建议的关系

```text
源单位和 uncertainty ──来源/参考──┐
                                ├→ 受质量配置约束的逐实体工作容差
用户显式选择的质量配置 ──硬约束──┘            ↓
                         构建 / 验证 / 派生数据 / 可选修复
                                            ↓
                         实际几何残差 + 容差变化 + 源语义对账
                                            ↓
                          按冻结的独立门槛验收后发布
```

这是对现有SMLib容差机制的导入/修复使用契约，不是另起一个无关联的全局epsilon，也不切换当前未完成的新容差方案。

## 谁提供质量要求

建议调用方显式提供或选择一份已定义、可复用的配置。配置可以在应用启动时选定，不要求每个文件重复人工输入全部参数；但每次请求都必须能确定实际采用哪份配置及其数值。

在未建立并定标生产默认策略前，不从源uncertainty或内核默认值自动生成“满足用户精度”的承诺。缺少质量配置时可执行诊断/画像并生成建议，不能给出满足某个未声明精度的成功结果。诊断路径的工作条件同样记录，且不得触发未授权几何修复。

配置至少分别包含以下量，而非单个`tolerance`：

| 项目 | 控制的含义 |
|---|---|
| 定义几何转换误差门槛 | 源定义到规范/目标表示的允许数值偏差，不许可静默拟合 |
| 几何一致性门槛 | 顶点端点、边面、源3D/pcurve等在对应语义下的允许残差 |
| 派生UV误差预算 | 目标派生参数数据在3D空间的允许误差及区域/分支条件 |
| 修复准入缺口与模型位移预算 | 能进入白名单修复的原缺陷，以及相对原始模型允许的变化 |
| 工作容差上限与增长预算 | 相关实体及传播涉及实体可使用的有效容差、全流程变化和修复变化 |
| 局部特征保护及过程限额 | 已确认的局部保护比、测量可信条件，以及迭代/资源/取消边界 |

几何不一致门槛、定义转换误差、修复位移不要求数值相等；它们判断的是不同关系。例如修后顶点恰在边上，gap可以接近零，但该顶点相对源点的移动仍必须独立受限。

具体数值及可用预设在验收票结合合成与真实模型定标；本票可以先决定显式参数化契约，不把一个未测常数当生产默认。所有长质量在规范mm和已选检查空间中表达，角度/参数空间量单独声明。

## 源 uncertainty 怎样使用

- 保留原数值、量纲、representation context和规范换算值，标明缺失或冲突。
- 可以用于产生工作精度建议、诊断源声明与所选要求的差异；不能直接替换验收门槛、授权位移或放宽最大容差。
- uncertainty缺失不等于必需长度单位缺失：前者可在已明确的质量策略下报告缺失并继续检查，后者仍按已定规则拒绝。
- 源声明较粗但独立几何检查较好时，不自动把文件声明改成更高精度。是否对源声明另设准入要求可由质量配置表达；成功报告须限定实际验证的质量含义。
- 不用文件级最大uncertainty抹平各representation的差别，也不忽略混合单位。

## 逐实体工作容差怎样建立

1. 在可信源/中立结构上测量需要表达的残差，并记录测量方法、已知误差界、未知项及数值可靠性。
2. 为每个目标实体选择能覆盖已验证残差及构建要求的工作值；源uncertainty与内核默认仅是有记录的输入/候选，不能无条件覆盖独立限制。
3. 按内核实际邻接/级联契约传播，并对传播涉及实体同样检查绝对上限及局部保护。某face的变化可能影响多条edge/vertex，不能只审批该face。
4. 如果所需工作值或传播后的有效值超过配置，返回“当前质量配置下无法构建/无法保证”。不能把超预算值写入后成功，也不能把字段截小使报告看起来合格。
5. `T_before`与源uncertainty分开。完整记录请求中的显式初始赋值、构建后、内核检查后、派生UV后、修复各步及最终有效值；新建ID仍沿来源映射关联。
6. 全流程增长从首次显式工作赋值/冻结基线追踪，修复阶段另分账，不能先由构建/AssertValid涨tol，再重设基线规避增长预算。中间峰值和最终值均检查。

这里的“选择足够值”不承诺求得数学全局最小容差。数值下限、无法配置的算法常量和映射退化需要探针确认；不能把当前默认值当可达到精度下限，也不能从setter能写任意值推断算法可靠。

## 算法有效阈值怎样处理

当前SMLib探针已见：两对象intersection getter为两者zone之和，approx getter也会随实体zone变化。因此记录存储字段不够，还需对关键消费操作记录它真正使用的阈值与来源。

但是，不能要求所有算法阈值都简单小于同一个几何误差门槛：较宽的候选搜索窗口与最终允许几何偏差不是同一语义。具体分类应为：

- 候选搜索、步长和收敛阈值：明确用途，由独立后验检查决定结果是否合格。
- 合并、视为重合、删除等可能改变定义模型的判据：只能在白名单、唯一对应和局部保护内使用，不能仅凭一个大XSectTol自动获得修改许可。
- 近似输出的精度阈值：由其单独误差预算约束，并验证实际偏差；不因属于某个getter派生值就默认正确。

如果关键阈值来源无法追踪、局部/参数映射失效或操作结果无法达到配置，记录未支持/无法保证。不得通过“内核返回成功”跳过此判断。

## 修复预算与这些值怎样连接

白名单、局部保护比1%和相对不可变修前基线的累计变化继续适用。位移、原始缺口、最终有效工作容差分别与其显式上限及`0.01 × L_guard`取更严格者，不能把一个值的剩余额度自动转移给另一个值。

源pcurve和3D几何超阈值冲突继续按已确认政策拒绝；修复模式也只允许已确认白名单，不因为有更大预算就自动启用拟合或任意取舍。

只增加实体tol、实际gap没有下降时标为容差协调，不标为几何闭隙。冻结的独立几何验收条件不能同时被修改。超预算、保护界不可信或检查无法支持结论时，拒绝候选并保留原输入与诊断。

## 建模以后怎么办

导入输出携带实际容差、质量配置标识及已验证范围。下游操作仍要按同类原则记录新误差与新tol，不能认为一次导入验收对所有后续算法永久有效。公开结果接口和模型生命周期由对应票确定；代表性查询/建模资格测试由验收票定义。

## 进入数值定标前的验证矩阵

这些是未执行的设计要求：

| 场景 | 需要排除的问题 |
|---|---|
| 源uncertainty缺失/很大，实际小残差 | 由源字段自动授权大位移或扩大质量门槛 |
| 一张面提高tol并传播邻接 | 只检查直接修改对象，漏掉相关edge/vertex及有效算法阈值 |
| 小零件、大模型局部微小特征 | 用整体尺寸选择tol吞掉局部细节 |
| 同形件不同单位、不同均匀实例尺度 | 单位/实例缩放没传到容差和独立验收 |
| 同一物理边界、不同参数化与周期侧别 | 用固定UV epsilon代替3D误差和区域判断 |
| 构建或内核检查自动涨tol | 操作status通过掩盖原始残差或reset增长基线 |
| 用户配置严于可保证条件 | 截小存储tol、继续返回成功，或偷偷升级到宽松配置 |
| OCCT与SMLib都返回有效但tol不同 | 把validity当作相同几何质量，而没有残差/定义/配置对账 |

先验证这些契约，再讨论生产预设与实际能力范围。真实模型库用于定标与找反例；导入链路尚未实现，不能先承诺全库修复成功率。

## 已讨论并获确认的政策

1. 质量/修复配置由调用方显式提供或选择，源uncertainty只作保留的参考与差异诊断；未提供时只做诊断，不自动宣称满足用户精度。
2. 逐实体建立与传播工作tol，记录关键有效算法阈值，固定独立验收；无法满足配置时失败，不放宽验收或截字段伪装。
3. 生产默认数值暂不设置；在上述契约的验证与模型库定标后另行决策。原1 μm/5 μm候选未批准。
