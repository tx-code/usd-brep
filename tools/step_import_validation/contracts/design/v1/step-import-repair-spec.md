## 1. 目标、边界与证据等级

目标是自行实现C++ STEP Part 21读取与实体解释，将AP203/AP214/AP242共同精确BRep子集转换为可精确查询、并按资格用于后续建模的SMLib模型。基本装配、重复实例、开放壳、闭合实体和空腔的含义必须保留。

强制约束：

1. 产品读取/转换链路不使用OCCT，也不把Truck/ruststep作为必经读取后端。它们的文档、源码和测试侧独立对照可以使用。
2. 默认严格导入；修复须由请求显式选择，在副本上执行已验证的白名单动作。源、已发布快照和已选质量门槛不受失败候选改变。
3. 所选请求全成全败。不得跳面、丢零件、改选最大实体或发布半成品；预先明确选择独立根及其完整依赖是允许的。
4. 不用网格或截图判定精确BRep正确，不修改既有USD体系，不扩大到通用格式导入、完整STEP写出或PMI编辑。
5. 私有模型只在本机使用；公开复现采用合成模型。此规格不授权提交、推送、PR、发布模型或开始实现。

“首版目标覆盖”“某阶段已实现”“某配置下已验收”“公开声明支持”是四种不同状态。未实现能力在增量版本中准确报不支持，不能因此把整个首版目标记作完成；已承诺项若不能实现，必须重新讨论范围，不能临时改名提高成功率。

当前证据截止2026-10-15：

## 2. 三个模块与内部数据契约

依据：[模块划分决策](wayfinder/step-import/tickets/03-module-boundary.md)，术语见[GLOSSARY](../GLOSSARY.md)。

```text
不可变输入 → 原始STEP文档 → 中立导入模型 → SMLib一次性候选
                 │                │               │
                 └──────── 来源、诊断、变化账本 ─────┤
                                                  ↓
                                  独立验收 → owning只读结果

显式修复请求 → 从同一源快照重新建立副本 → 白名单动作 → 全部重验
```

| 模块 | 核心职责 | 不得承担的职责 |
|---|---|---|
| 原始STEP文档 | 完整HEADER/DATA、记录ID/位置/原值、引用索引、复合实体组成和未知内容；按需提供类型视图 | 为让内核接受而改写源值、丢未知实体，或另复制一份全文件类型对象图 |
| 中立导入模型 | 解释精确几何、拓扑及每次使用、源pcurve/master、单位/参数、零件/实例、冲突与来源关系 | 含SmContext/SmFace/SmEdge/TopoDS指针；把尚有冲突的语义当已合格模型 |
| SMLib适配器 | 目标参数映射、专属候选所有权、构建副作用封装、UV/域/tol对账、检查及结果交付 | 修改中立输入；让调用者管理半成品Euler操作；依赖默认healer补救读错的语义 |

检查贯穿三者；修复是另一次候选执行。`SmBrepData`仅为目标适配器的可选暂存结构，不是中立格式，也不是可复用源数据。

中立模型至少表达以下信息，字段布局由内部实现确定：

- 文档、根、定义、occurrence、曲面/曲线、顶点/边/面/壳、每次边使用和pcurve的独立身份。
- source→neutral→target多对多对应；拆分、合并、添加缝后仍可追踪原实体和本次动作。
- 原物理单位、源参数区间/周期分支、源优先表示、目标参数映射的方向/法向奇偶性。
- 原几何与拓扑事实、测得的不一致、输入uncertainty及目标工作tol分别存储。
- 尚未支持、尚未测量、无法判定和被拒绝的必需内容，不能被“空数组”隐去。

来源ID不得使用native指针、PID或当前遍历下标代替。每个目标记录归属结果修订；源记录归属内容身份。新目标ID不重置修复累计基线。

## 3. 文件、实体与完整性范围

依据：[接受范围决策](wayfinder/step-import/tickets/04-parse-completeness.md)。下面是**首版目标清单，不是当前已支持清单**。

### 3.1 文件及依赖规则

- 接受自包含Part 21文本`.step/.stp`，完整处理所有DATA段、前向引用、简单/复合实体、嵌套列表、typed values、枚举/logical、数字、注释、字符串转义，以及`$`与`*`的区别。
- HEADER/文件实现级别、FILE_SCHEMA原文及AP/edition解释分别保存。文件版次与AP版次不是同一维度；只认出“AP214”等标签不授予转换资格。
- 全文件先建立可靠的记录索引，重复ID、破损语法、非法编码及歧义记录不能靠选根绕开；必需引用在完整相关记录可见后解析，不能因暂未读到而报丢失。
- 所选根按产品/表示关系确定，闭包包含几何、拓扑、上下文、单位、放置及装配关系；不能只从face正向走几何指针。无法唯一解释根/表示角色时报告范围歧义，允许调用者重新明确选根，不自行猜测。
- 普通引用图允许其语义允许的环；装配层级等应无环关系单独检查，并限制遍历资源。未选范围的问题依影响分类，但全局语法/ID歧义不能被局部忽略。
- 已证明不影响所选语义的附加元数据原样保留并诊断；必需或影响未知的内容不支持则拒绝。不能以“没有直接被face引用”为无影响证明。
- ZIP/STEP-XML、外部文件引用、签名以及未支持的扩展语义明确拒绝；不偷偷忽略后称自包含文件完整导入。

### 3.2 能力族与必需语义

| 能力族 | 首版目标实体/表示线索 | 必须验证的语义 |
|---|---|---|
| 原始文档 | HEADER、DATA、简单/复合实体、引用及字符串 | 全段读取、constituent完整、源位置、未知内容不丢失 |
| 坐标与放置 | CARTESIAN_POINT、DIRECTION、VECTOR、2D/3D轴放置 | 点/向量/方向含义、合法缺省轴与非法轴的区别、位置/朝向 |
| 上下文与单位 | 几何representation context；SI、conversion-based、length/angle单位及uncertainty复合结构 | 继承/属性完整、量纲和换算链、混合context，不能全文件套一个scale |
| 曲线 | LINE、CIRCLE、ELLIPSE、TRIMMED_CURVE、非有理/有理B样条及Bezier/uniform/quasi-uniform变体 | 精确定义、degree/knots/weights、裁剪selector和sense、闭合区间、端点/参数对应 |
| 曲面 | PLANE、CYLINDRICAL/CONICAL/SPHERICAL/TOROIDAL_SURFACE；B样条曲面；常用旋转/线性拉伸面 | 源UV/目标UV、轴/半角/半径、生成曲线、周期/奇异及自然域 |
| 曲面上的曲线 | PCURVE、SURFACE_CURVE、SEAM_CURVE | master、全部associated表示、同面缝两次使用和独立UV分支 |
| 顶点/边/环 | VERTEX_POINT、EDGE_CURVE、ORIENTED_EDGE、EDGE_LOOP、VERTEX_LOOP | 共享身份、各层sense、非零闭合边、奇异UV行程，不能按坐标焊接 |
| 面与壳 | FACE_BOUND/FACE_OUTER_BOUND、FACE_SURFACE/ADVANCED_FACE、定向面/壳、OPEN/CLOSED_SHELL | SET与有序环的区别、外环/孔、面相对曲面方向、开放/闭合含义 |
| 实体和空腔 | MANIFOLD_SOLID_BREP、BREP_WITH_VOIDS及对应精确表示 | 外/内壳所属区域、void标志、内外分类和材料体积 |
| 开放模型 | MANIFOLD_SURFACE_SHAPE_REPRESENTATION、SHELL_BASED_SURFACE_MODEL等支持表示 | 保持开放类型，不因缺少实体封闭性而自动修补 |
| 基本装配 | 产品/shape关联；REPRESENTATION_MAP/MAPPED_ITEM；常见representation relationship/变换及装配使用关系 | 定义/occurrence分离；映射和产品关系路径对账；不重复计实例、不丢变换 |

上表是语义族索引，**不是逐AP/edition的属性实现表**。实现前必须建立机器可检查的能力清单：每个受支持schema/版次、实体组合及继承/属性类型、必需依赖、约束、参数规则、target构造方式、正负例、资格状态和精确拒绝原因。复合rational实体不得丢掉权重部分；属性顺序不能由近似的同名实体猜测。

P0完成清单格式及首个切片的精确条目；P1/P3/P4/P5各自在进入相应能力编码前补齐本族条目。没有经核对的条目只能报告Unsupported，不能直接分派到通用converter。具体AP/edition、Part21编码规则和未覆盖约束仍须在清单中逐项核实；本规格不虚构一份已验证的完整EXPRESS模式。

### 3.3 明确延后

复杂offset/未列入的swept表示、CSG、tessellated/faceted-only、非流形、独立线框/点集、未列入的曲线类型、非均匀缩放/剪切、外部文件装配、完整PMI/GD&T和STEP写出。必需依赖命中这些类型时拒绝，不删去依赖继续。

## 4. 单位、参数与装配契约

依据：[单位/实例决策](wayfinder/step-import/tickets/05-context-assembly.md)、[精确参数决策](wayfinder/step-import/tickets/06-exact-brep.md)。

### 4.1 单位及参数映射

规范长度为mm，物理角为rad；保留源量纲、原值、context和换算因子。必需单位缺失或矛盾拒绝。uncertainty缺失与单位缺失不同，前者可按明确质量配置继续检查并报告缺失，不能自动获准放宽误差。

物理单位、曲线自身参数、源surface UV和目标UV分别处理。NURBS权重、knots、UV不因长度换算一律乘scale。每类几何必须给出source→canonical→target的点/参数对应，以及区间、周期、导数/法向方向和逆向关系；nonlinear映射不能用一次线性scale伪装。

裁剪点与参数selector的解释、source 3D边参数与pcurve自身参数的配对必须有依据。端点投影有多解、闭合周期不明或数值范围不能可靠承载时拒绝/无法判定，不能选第一个解或将同端点区间缩成零。

必要数值不能在目标数域安全表示时区分目标数值范围限制与源非法；不通过溢出、下溢、NaN、单位矩阵或零值替代继续。

### 4.2 定义与实例

- 零件定义保留local几何，多occurrence共享定义，实例保留独立身份、层级与变换；不按位置重合合并实例。
- 首版支持平移、旋转、均匀缩放和镜像，拒绝非均匀缩放、剪切、零尺度、奇异或非有限变换；不隐式居中/改轴/转到USD坐标。
- 每条关系明示变换的from/to及组合顺序，单位换算只作用一次；多表示/装配路径若不一致则诊断，不能任选一条。
- 镜像和参数交换的方向按源每一层sense和目标法向奇偶性推导，以非对称模型、内外点和有向边界验证，不能靠对称盒体或一个XOR公式认定全面正确。
- occurrence建模副本应用完整变换，并把长度型质量/容差按实际尺度与检查空间对账。共享定义验收不自动授予所有实例尺度下的质量资格。
- 多实例装配不是隐式几何union；重叠实例仍是各自occurrence。查询/建模资格区分local定义和经变换的实例。

## 5. 精确BRep构建与验收

### 5.1 源优先表示和目标UV

源3D曲线、所有源pcurve、所属surface、master、每次使用方向和周期分支完整保留。尊重源优先表示，并检查其他表示是否一致；超阈值冲突严格失败。源pcurve优先时不得丢弃后改信3D/drop结果；目标无法保持定义则不支持。

定义性曲线/曲面不静默拟合。等价重参数化、节点插入或目标seam/拆分须逐种证明保持形状和使用语义、完整记录来源。移动定义点、删除特征、补面、放宽工作tol不是普通等价规范化。

目标派生UV可以在独立预算内近似，但须保留源定义，并验证三维lift误差、参数覆盖、环区域、方向、周期分支及奇异行为。少量端点/中点通过不足以证明全域一致。源pcurve不能因目标UV属于cache就变为可丢弃信息。

### 5.2 周期、退化及区域

- 同一源edge只保留一份共享身份，每次face内使用独立；同面缝上的两个occurrence和UV分支不得按`(face,edge)`去重。
- 不把全部UV取主值后丢掉绕行；三维重合不能决定缝侧或选取区域的补集。
- 闭合但非零边保留，不按同端点或统一短边阈值删除。
- 三维塌缩但UV有行程的源边界、vertex-loop和极点要有显式目标对应；不得造一条微小3D线或编码成会被跳过的type3后报成功。
- 外环/孔/空腔由源语义和独立区域检查确定，不依赖SET出现顺序、全局计数或单独volume接近。开放壳保持开放。

原生球可回建的证据不等于STEP退化边映射已证明；原生solid-cylinder探针实际走等半径cone，也不授予全部SmCylinder/STEP参数路径资格。

### 5.3 首个构建路径与约束

首个平面/盒体纵向切片采用受控SmBrepConstructor作为实施基线：显式共享顶点/边、精确3D曲线、已知parameter limits、明确区域/void和面域；EndShell(FALSE)。这是已确认的首切片计划，不是已经实现的声明，也不锁定公共接口或所有后续几何族。

每个候选从根分配时即由owner持有；surface/curve在候选context材料化并按一次性所有权移交，避免重复移交或依赖已拥有surface的未验证复制支路。反向edge顶点参数按已测可执行语义构造，再独立核对curve min/max与use端点，不凭注释猜。

已有UV时不能仅靠关闭bMakeUVTrimCurves延后安装。已测适配方式是建图阶段不提供UV，随后为每次occurrence用fresh copy经受支持setter装入SAME成员；同指针重调setter可能不迁移归属。实际偏差和预算必须验证，不能照抄探针max-distance=0掩盖误差。

MakeTopologyFromData保留为内部候选，但必须单次owning staging、域/tol/owner前后对账；不能复用目标析构后的staging。禁用隐式heal/analytics并不消除裁域、tol下限或其他副作用。切换后端必须跑同一契约，不设置失败后自动换后端以隐藏错误的fallback。

有几何radial排序或fallback的支路必须与源邻接对账；未知sector、未验证奇异支路或不受控副作用不能靠继续构建取得资格。正例没有显示必须改内核的阻碍；以后若需要内核修正，须独立最小复现、审计和回归，不顺带修网格。

### 5.4 独立验收顺序

| 层 | 必查内容 | 不通过时 |
|---|---|---|
| 源完整性 | 所选依赖闭包、实体/继承/属性、单位、范围、未知影响分类 | 不构造native指针；源错误与不支持分开 |
| 中立语义 | 方向、共享/使用身份、master、一致性、装配、区域及参数映射 | 拒绝，或仅在显式修复计划下进入可验证副本 |
| target前置 | counts/indices、所有权、可遍历图、端点、face域、UV成员和区域 | 停止不安全深验，丢弃候选 |
| 内核检查 | ValidatePointers的状态与全部reports；前提满足后一次LEVEL2/WALK | 状态成功不覆盖reports；未知断言不默认为warning |
| 独立几何/语义 | 源→target定义、边/面/UV、孔/空腔/内外、实例；实际残差/界 | 未证结论为Indeterminate，不接受必需检查 |
| 质量与变化 | 各阶段有效tol/阈值、派生误差、规范化/修复和累计保护 | 不放宽或截字段，拒绝候选 |
| 消费资格 | 请求必需的精确查询/截面/建模范围 | 必需资格未满足不交Accepted |

validator可物化UV/缓存或改变tol，检查前后必须对账；公开只读快照不允许这些动作悄悄改写验收基线。

误差证据区分代数等价/结构保持、带数值舍入控制的保守界、有限抽样和无法判定。一般B样条/组合映射需可靠界估计或等价构造依据；分母/奇异域/局部保护无法可靠界定时不能用固定采样代替承诺。具体检查器和适用条件是P0/P3交付，不声称目前已实现。

## 6. 显式质量配置与受限修复

依据：[修复决策](wayfinder/step-import/tickets/07-repair-budget.md)、[容差机制研究](wayfinder/step-import/tickets/12-tolerance-contract.md)。

### 6.1 质量配置

调用方显式选择一份可复用、版本化配置；可由应用启动时选定，不要求每个文件人工重输。缺配置只可inspect，不能自动承诺某个精度。

| 参数族 | 控制对象 |
|---|---|
| 定义转换误差 | 源定义到规范/target表示的允许数值偏差；不许可静默拟合 |
| 几何一致性 | 顶点/边端点、边面、源3D/pcurve的语义对应残差 |
| 派生UV | 三维误差、参数覆盖、区域/方向/分支及检查证据要求 |
| 修复准入和位移 | 原缺陷最大缺口、相对冻结基线的最大变化 |
| 工作tol | 逐实体绝对上限、增长上限、中间峰值及传播后的有效值 |
| 特征保护 | 可靠局部保护尺度及已确认1%限制，不能由整体bbox代替 |
| 验收/资源 | 必需资格、证据强度及迭代/采样/时间/内存等过程限额 |

source uncertainty、内核工作tol、独立验收门槛和修复预算分别记录。source uncertainty只作参考/告警，不自动许可移动或放宽接受条件。生产默认数值延后定标；早先1μm/5μm候选**没有采用**。

### 6.2 tol账本

为每实体记录：首次显式工作赋值T0、构建后、检查后、派生数据后、每个修复步骤后和最终值；记录传播涉及对象及关键XSect/Approx等实际消费阈值和用途。构建中的自动增长不能被重设基线抹掉。

实际原生规则作为约束输入：例如数据构建可能取max(entityTol,brepTol)，face setter可能传播到edge/vertex。设置了字段或forceSameTol不表示已经达到质量配置。

工作值应覆盖已验证残差和构建要求，又满足显式上限/保护；无法同时满足就拒绝。不得截小存储tol伪装合格，也不得以大XSect搜索窗口为定义修改授权。候选搜索、收敛、视为重合和近似输出阈值按用途区分，不能全部套同一个epsilon。

### 6.3 修复白名单及不允许动作

| 逐项验证后可启用 | 条件 |
|---|---|
| 连接/方向纠正 | 唯一可判定、保留区域与使用含义，不以猜测修补源歧义 |
| 已有精确几何上的端点/裁剪校正 | 原缺口、位移、tol增长和局部保护均在预算内 |
| 重复顶点/等价边合并 | 等价与配对有证据，不跨零件/实例，不吞特征 |
| 已有边界受限缝合 | 唯一匹配、预算满足、修后全部重验；不自动封闭源开放壳 |
| tol协调 | 有实测依据，传播对账；gap不变就不称闭隙 |
| 派生参数数据修正 | 尊重源master，不把authored源定义当可随意删除cache |

不自动删小边/面/孔/薄壁，不补面/造缺失边，不拟合定义曲线/曲面，不任意覆盖3D与源pcurve冲突，不启用全healer序列或禁用/TODO阶段来冒充白名单。无已验证动作的冲突拒绝，不因预算较大而扩大操作范围。

### 6.4 保护与失败

对有关修复分别要求：

```text
原缺口     ≤ min(显式缺口上限, 0.01 × L_guard)
最大位移   ≤ min(显式位移上限, 0.01 × L_guard)
修后有效tol ≤ min(显式tol上限, 0.01 × L_guard)
全过程tol增长及中间峰值 ≤ 各自显式增长/峰值预算
```

L_guard必须可靠反映受影响邻域内的保护特征，例如薄壁、孔/窄槽和非参与边界间距；不能只取待修边长度或全模型尺度。计算方法及保守性待专项验证，测不准就拒绝自动动作。每个量独立限额，不互借额度。

基线冻结为源/修前模型，合并/拆分后沿来源对应累计，不能由新ID或新步骤清零。每步和最终检查均不得产生新问题。原始严格失败也可从源快照复制中立数据申请修复，但只能在可安全解释/测量的部分开始；不把损坏native图交给healer。

失败时丢弃整个修复候选，保留源和诊断；旧合格快照仍可用，不冒充本次修复成功。干净输入不应发生定义漂移或无依据tol增长，重复修复不得持续漂移。

本设计使用并约束当前SMLib实际容差机制，不通过切换尚未完成的NEWTOL方案来代替契约验证。边界判断使用可支持结论的误差界；测量区间跨越预算边界时为无法判定，不能四舍五入成通过。

## 7. 返回模型、诊断、修复报告与发布

依据：[结果与所有权决策](wayfinder/step-import/tickets/09-public-result.md)。

### 7.1 调用语义

```text
inspect(input, limits) -> 源快照? + 检查报告，始终不交付可建模目标
import(input_or_source_snapshot, request, cancel) -> ImportOutcome

request = 明确的根选择 + 显式质量配置 + 资源配置
        + 可选显式修复计划 + 必需下游资格

ImportOutcome = 终态 + 已接纳模型? + 源快照? + 报告
```

| 终态 | 模型 | 契约 |
|---|---|---|
| Accepted | 完整owning只读快照 | 本请求必需内容/检查/资格全部满足，报告与快照对应 |
| Rejected | 无 | 源非法/不一致、必需能力不支持、超配置或证据不足等，给出准确阶段/原因 |
| Cancelled | 无 | 用户取消赢得提交裁决，候选撤销完成 |
| Failed | 无 | 内部/基础设施/异常资源故障，不能据此断言源非法；报告可不完整 |

已配置限额的准确拒绝与意外内存分配故障分别记录。超时、用户取消、worker崩溃和失联未知原因不混为一类。错误码/阶段可供程序判断，不能要求调用方解析一段RuntimeError字符串。

Accepted不表示任意布尔/圆角均可靠。每项资格分别记录通过、未通过、未运行或无法判定及操作/参数/质量范围；请求必需资格未满足不交Accepted。

### 7.2 所有权与失败后的源

- 成功模型拥有全部native根、来源关系及context生命期，不依赖任务或staging存活。有效子对象视图持有owner/租约，父结果释放不留下悬空引用；最后一个有效owner释放后按顺序清理。
- 查询侧只读的是定义及其验收基线，不承诺任意native查询线程安全。可能改定义/tol的检查在副本执行；新只读接口不能泄出可变native句柄。
- 建模通过显式操作得到某零件/occurrence的独立可编辑BRep。原快照和其他实例不变；该操作自身需要资格及独立失败结果。
- 输入已完整捕获、且资源保留策略满足时，失败可返回不可变源快照供定位和显式修复重试。IO未完成时可没有源快照，报告其范围；路径不等于冻结内容。
- 源快照的输入缓冲/本机不可变暂存绑定内容hash，不受原文件后续改写影响；不默默保留一个可变mmap却声称源已冻结。保留预算不满足时准确拒绝或要求重新提供相同内容。
- 所选范围内要求原样保留的未知非关键元数据和来源证据，必须由模型/源证据owner持有所需不可变记录；不能因没有公开完整源快照句柄而删掉这些内容。有效句柄仍需要的存储不得被保留策略静默释放；预算不足要显式处理，不能留下悬空引用或假装仍可重试。
- 报告独立保存，不强行保活整个大模型/整份源字节；原文摘录和来源定位的可用性明确记录。失败native图不作为修复输入跨请求保留。

这是新接口的实现目标，不能声称现有SM_API/Python borrowed对象已经具备该owner行为。公开稳定化必须等生命周期测试通过。

### 7.3 三类报告明细

| 明细 | 必需事实 |
|---|---|
| Diagnostics | 稳定code、严重度、阶段、作用范围、因果关系、源位置/实体与occurrence路径、实测值/单位/阈值和证据强度 |
| Normalization | 单位/参数转换、目标必要的seam/分面及派生UV；源→目标对应和保持语义的依据 |
| Repair | 冻结基线、动作/尝试状态、前后实体映射、缺口/位移/tol传播、累计/中间峰值、保护/预算、候选是否接纳或撤销 |

报告绑定request ID、内容hash、选中范围、质量/资源配置、修复计划、实际源码/二进制/检查器版本和结果修订。Native指针不作持久ID，未知/未测不填零，丢失的报告不伪称完整。

源pcurve/master、几何等价规范化和修复动作不能混成“healing成功”。只有tol变大而gap不变时标为容差协调；无修复或只有等价转换时明确无修复变化。

### 7.4 取消与应用接入

取消是请求，不是立即停止的保证。合作取消在安全边界检查；不可中断native调用先安全返回再废弃候选，不能强杀线程或中途销毁context。

取消和成功通过唯一终态提交点裁决：取消先赢就阻止Accepted，撤销完成后Cancelled；成功先赢则迟到取消为TooLate/AlreadyCompleted，不销毁交付模型。意外故障仍准确记录，不用取消掩盖原因未知。

库内交付和应用接入分开。模型owner和报告固定后才交付；应用用expected workspace/document revision及request generation/token作原子比较，匹配时自动接入完整结果，无须逐次人工确认。

旧任务不覆盖新编辑/新文档；不匹配时保留“导入成功、尚未应用”的结果，报告Conflict/Superseded。库内成功后的停止应用意图只阻止尚未发生的接入，不改写导入终态；已接入结果的恢复属于应用撤销。

## 8. 资源、执行隔离与版本维护

### 8.1 两层执行

1. C++核心同步返回本进程owning模型，合作取消，遵守native进程内串行约束；独立context不授予任意多线程并发资格，也不保证进程内崩溃恢复。
2. GUI/批量应用需要硬取消、硬超时或崩溃隔离时，将完整候选放入独立worker。并行按进程扩展；同worker一次一个native调用。

候选worker不得承载旧已发布模型的强制终止生命期。成功后可将worker/session和模型句柄的owner可靠交给结果；job结束不回收已交接模型。协议必须处理提交/取消竞争、重复消息、owner交接确认丢失和父侧回收。

owner交接按以下先后关系设计，具体IPC字段在P6确定：

1. worker形成完整候选和冻结的必需报告，发出带request/result身份的Prepared；这还不是成功交付。
2. 父侧建立独立于job的模型owner/租约，校验结果范围、版本和报告完整性；未确认取得生命期责任时不能提交Accepted。
3. 协调者以一次终态裁决检查取消。取消先赢则释放临时owner并撤销候选；成功先赢则固定Accepted与其owner/报告。
4. 只有结果owner已保活worker后，才释放job的候选持有责任。交接ACK丢失以结果身份幂等处理，不能因job结束/ACK超时销毁已被结果owner持有的模型。
5. owner取得失败、worker死亡或交接原因不明时，不交伪成功；清理未发布候选，保留最小已知故障。应用接入仍是之后独立的revision/token提交。

worker模型只能通过所属会话访问，不是一个可跨进程传递的SmBrep*或现有Python Brep。首版隔离封装先提供已验收的模型信息/精确查询及生命期代理；跨进程重建成本地BRep的格式、tol/来源保持与重验另列扩展验证，不是P6默认已有能力。

如果请求要求“隔离后返回本地可编辑BRep”，而桥接能力尚未验证，应在准入时明确拒绝该执行能力，不能返回远端句柄冒充满足要求。本进程核心的独立建模副本与worker代理的能力分别声明。

进程退出只隔离其地址空间，父侧仍须清理OS句柄、输入/结果暂存、租约、部分报告和job状态。生产协议未验收前不承诺“强杀后完整可用”。极端OOM/崩溃可能无法返回完整核心结果；隔离层保留最小已知故障记录及最后确认阶段。

### 8.2 有界资源

资源配置至少声明：输入字节、记录/引用数量、列表/引用深度、字符串与单记录大小、依赖访问次数、实例数量、目标实体、迭代/测量次数、工作内存、源保留/临时磁盘、报告大小、截止时间和取消宽限策略。

- 每个限制标明强制点、hard/cooperative性质与适用执行方式；没有实现的硬限制不能被宣传为已生效。
- 在计数乘加、分配和递归前检查溢出/限额。避免同时持有整份文本、多份通用AST、全量typed图及native副本。
- 必需验收证据不能因日志限额被截掉后继续接受；调试日志可有界截断并标明。
- 本进程时间/内存软检查不等于OS硬限制；要求硬限制的模式必须具备并验证对应进程机制，否则拒绝该资源契约。
- 大文件可分批读取和按需解释，但完整性规则不因流式处理改变；续跑只复用内容/配置/版本完全一致且有效的证据。

具体生产资源档位由P0建立字段与验证机制，P7实测定标；当前没有隐含无限模式或虚构可保证的内存/秒数。

### 8.3 版本与兼容性

能力清单、质量配置、诊断报告、测量器和二进制分别带版本。首次公开SM_API/Python前冻结其小接口与owner语义；原始/中立模型和私有构建器继续内部化，不因公开一个结果句柄而冻结整个图。

新增实体/版次/修复动作必须增加依赖规则、反例和资格证据。改变源解释、默认值或质量含义须明确版本化，不能复用旧通过结果。首次公开兼容承诺的具体版本策略在P6列清，暂不假定二进制/序列化永久兼容。

### P0：先让正确性和失败可被检查

交付物：

- 明确每族schema/版次/实体组合/必需依赖的能力清单；首个平面切片的属性/约束/单位规则核对完成。
- 为源位置/ID、定义/occurrence/use、映射、诊断及Accepted等结果建立内部可测试契约。
- 一组版本化合成测试配置，数值来自夹具尺度与明确真值，覆盖可达配置、不可达配置和预算边界；不是生产默认。
- 独立解析/Bernstein/有理B样条/区域/装配真值的来源和误差说明；区分检查器误差与被测模型误差。
- 首个top-down适配操作序列及所有权转移表、无隐式stitch/heal、UV后装、域/tol/void检查清单；待证项进入对应门槛。

退出：每项首个切片承诺都有正例、拒绝例和判定方式；不靠SMLib自身构造/往返作唯一真值。测试执行器能隔离普通错误案例并记录实际DLL路径/hash，原生占位heap计数不充当资源证据。缺少可判定验收的能力不得开始宣称实现完成。

### P1：自有文件读取与可信源文档

交付完整Part21读取、引用索引/按需访问、源快照与有界检查、inspect入口。核对三类AP/edition清单的最小有效文件，不仅替换HEADER就声称符合另一AP。

退出必测：

- 多DATA、乱序/前向引用、简单/复合rational constituent、`$`/`*`/typed value/嵌套列表、转义/编码与源位置保持。
- 重复ID、悬空必需引用、损坏数字/字符串、未知必需内容、扩展载体拒绝；循环按语义分类。
- 改变记录ID和顺序不改变所选语义；未选根不被自动加入，必需子件不能被删出闭包。
- 输入在原路径被改写后不影响已捕获源快照；内存/临时文件/日志限额准确生效，取消不产生伪完整源。

阶段只交源与检查报告，不交可建模目标，不将inspect通过记为导入成功。

### P2：第一个完整但范围窄的精确导入

范围：点/方向/放置/单位、平面与直线、共享顶点/边、定向边/环/边界/面、开放壳与平面闭合实体；不依赖圆弧/周期/NURBS/装配/自动修复。

退出必测：

- 开放带孔平面、两面共享一边、闭合盒体；分别以明确顶点/边界/区域、解析面积/体积、内外点和方向真值对照。
- source→target定义、共享身份、每次use及UV正确；反向edge的端点语义、SAME-owner归属、void/开放类型和域不被暗改。
- 同形不同合法长度单位/轴放置等价；未知必需几何、缺单位、缺引用、超质量及所选请求任一必需根失败时全拒绝。
- model/view持有与释放顺序、报告独立保存、源快照重试；普通构建失败/安全边界取消不交模型，已发布模型不变。
- 显式T0、构建/检查/UV后有效tol、关键阈值及几何残差满足测试配置，不因validator成功略过对账。

仅内部C++入口，先证明本进程结果。所需最低精确查询资格必须完成；尚未验证的下游建模操作明确未授予。P2通过不等于全部AP或首版完成。

### P3：按几何/拓扑能力族扩展

建议顺序：圆/椭圆与裁剪→解析面→非有理/有理B样条及变体→旋转/拉伸→完整pcurve/master及周期/奇异组合。顺序可按依赖调整，源到target参数契约必须先于该族转换编码确定。

每族退出必测：

- 独立求值/参数域/导数及有向法向，非均匀knots、rational权重、端点/内节点连续性、周期区间及合法奇异处预期行为。不能把奇异点法向未定义误判成一般源错误。
- 不同源/目标参数范围、轴/UV交换、trim point/parameter selector、source edge与use/bound/face的合法方向组合，避免只用对称模型掩盖错误。
- 3D优先、pcurve优先、多pcurve、超阈值冲突、不支持优先定义；定义性拟合不能被派生UV预算掩盖。
- 同面双seam、跨缝孔与多周期分支、两端同顶点的完整圆、球极点/锥顶点、source vertex-loop和UV有行程的塌缩边界；不能删type3后计成功。
- 闭合实体/空腔/开放壳独立内外/区域检查，不能漏设void后只看validator；规范化前后多对多对应可追踪。
- 适合该族的可靠误差/区域检查。检查不足则Indeterminate，该族不得晋升；仅native球/圆柱回建不算完成此门槛。

source合法但目标类型/数值域/参数映射无法可靠承载时准确报不支持，不能把它改成源非法。目标覆盖族若因此无法完成，保留阻塞并重新讨论范围，不擅自将其从首版清单移除。

### P4：定义、装配与可编辑实例副本

交付基本产品/shape关系、mapped-item及常用relationship变换路径、定义复用和层级；仅使用已验收的几何族。

退出必测：

- 非对称零件的两次重复实例、三层嵌套、同位置不同实例、无引用循环的共享定义；不拍平、不重复计装配路径。
- 混合mm/cm/m与明确转换制长度/角单位、旋转+平移组合、正均匀尺度、镜像与双镜像；点/法向/面积/材料体积和内外含义符合独立变换真值。
- 变换方向错误、双重单位缩放、非均匀/剪切/奇异、外部引用、装配循环和必需子件失败准确拒绝。
- 独立实例副本修改不改变原快照/其他实例，释放任一方不使另一方悬空；local/global检查空间和尺度后的质量要求明确。

本进程materialization先通过；跨进程本地副本不因本阶段的本地复制成功而获得资格。

### P5：逐项启用受限修复

每个白名单动作独立拥有最小故障、修复准入条件、唯一性判据、影响集合、预算/保护检查和完整失败行为。先证实作用对象与残差，再选择原生helper；不以SM_HO_ALL或“heal返回成功”作为实现。

退出必测：

- 预算内唯一缺陷修复后重过源/目标一致性、区域、质量和必需下游资格；有未授权变化或新问题就整候选拒绝。
- 恰在边界、刚超边界、测量界跨边界、累计多步超限、中间峰值超限、face→edge/vertex传播与新ID不重置预算。
- 薄壁、小孔、近邻非参与边界、配对歧义、无法可靠得出L_guard时拒绝；不能拿整体模型尺寸吞小特征。
- 修复off/on分开记录；干净输入不漂移，重复执行不持续变化；只增tol的动作明确不是闭隙。
- 严格导入已失败但源可解释时，从源快照新建修复候选；缺定义/单位、未支持master或非法源结构不能被猜测修补。

注册表只启用已通过动作；未通过白名单项保留为未实现/未支持，不能把“属于白名单”当动态有效性证据。

### P6：公开接口、worker和应用提交协议

可分内部C++稳定化、本地SM_API/Python owner、应用worker三个增量；每一增量仅暴露已通过的能力。原始/中立格式和构建器保持内部，不提前要求GUI用户选择native后端。

退出必测：

- 结果/定义/实例/face/edge/geometry view的保活与销毁，context最后销毁；独立可编辑副本与原快照互不影响；报告可脱离模型长期保存。
- 取消先赢/成功先赢、不可中断调用期间取消、超时和故障同时出现；每个request只一个终态，迟到消息不发布候选。
- worker在读取、构建、验收、报告、owner交接前后普通失败/崩溃/强终止；父侧不泄露句柄、临时文件、未接管进程或结果租约。
- 成功worker被模型owner接管后job可结束；旧模型worker不被新候选取消；跨进程句柄校验与失效诊断明确，不能传native指针。
- expected revision/token匹配时完整模型+报告一起应用；旧任务、用户新编辑/切文档、重复提交、owner交接确认丢失不覆盖当前状态。
- 本地C++/SM_API/Python与worker代理按相同结果语义运行，差异能力显式列出。测试例外和未验证保证不能被包装层隐藏。

首版worker隔离成功不要求未经验证的跨进程精确BRep物化。若未来要暴露现有本地Brep，须另过源/定义/tol/参数/来源/重建/重验门槛，不通过USD单tol或无隔离重跑绕过。

### P7：模型库定标与正式能力晋升

先冻结能力范围、检查器、配置、二进制和样本清单，再逐层执行。依据四层验收政策，初轮目标为60固定、20未见盲测、8大型资源样本；均未选取或运行。按内容hash去重，盲测与设计/调参/固定集严格隔离，实际集合与覆盖缺口可审计。

退出条件：

- 声明矩阵的合成正/负/等价变换全部符合预期；已判定范围内且源有效、配置可达的固定真实案例通过。
- 盲测没有未裁决错误接纳；一旦用于调参就转回归并补新盲测。与独立reader分歧逐项核对/最小化，不投票裁决。
- 大模型在声明资源内成功或按准确原因拒绝；取消、峰值内存/磁盘、日志体积、恢复/续跑与结果版本不混代。
- 代表性精确查询、平面截面以及副本平面切割/适用裁剪有原生控制和独立真值。原生控制失败也不授予该项资格，不误报源文件坏。
- 零已知错误接纳、静默丢必需内容、超预算通过、未声明部分发布；争议/证据不足不计通过。
- 生产质量/资源预设经定标后另作明确决定，或明确继续只接受调用方配置；不沿用未批准1μm/5μm。依据实际范围发布能力清单和限制，之后再逐批扩至4049库。

当前没有任何真实导入/修复成功率，也不要求盲目让所有4049文件都成功；已承诺能力、合法源与配置可达性必须先准确分类。

### 10.2 独立参照与争议裁决

主要参照是明确的解析/有理B样条、拓扑和实例真值；SMLib validator、原生构造control、OCCT等独立reader各提供一层证据。不能仅凭双方往返一致排除配对错误，也不能凭reader多数成功裁决。

对照前统一所选根、单位、几何/参数与自动修复策略，记录reader的实际tol变化。分歧先查范围/语义/变换，再最小化成可独立判断的合成复现。无法裁决列Unresolved，冻结受影响能力的晋升；不把它计作通过或直接定性源文件坏。

采样可以找反例，但不自动提供连续最大误差证书。每项检查记录方法、覆盖、数值可靠性及边界；无法满足请求证据要求则拒绝/无法判定。全局面积/体积只能辅助，不能独自证明孔、缝、局部特征、实例均保留。

|---|---|---|

既有179 HEADER和40实体画像属于设计已见证据，不冒充盲测；40中的6个截断前缀不算完整几何验收。清单/真实文件名映射只留本机，报告用匿名ID/hash，公开仓库不含原模型。

不得用HEADER识别比例推断全库分布或成功率。当前4049是清单规模，不是目标零失败承诺；正式能力仅按声明范围、源有效性、配置可达性和实测证据晋升。

### 10.4 每次运行的最小证据包

输入hash/来源身份、根选择、能力清单及schema版本、源码/补丁/实际DLL hash、完整质量/资源配置、修复计划、检查器版本、执行模式、逐阶段状态、逐实体tol/关键阈值及残差/界、变化映射、所有权/取消/资源证据和终态。

统计区分：接受、准确不支持、源非法、构建失败、验收失败、超预算、崩溃、超时、取消、资源超限、未运行和待裁决。预期拒绝可以是测试通过，但不是模型导入成功；明确本轮实际运行/复用/测量数，不能零测量报零问题。

续跑仅复用所有身份/配置/版本匹配、已完成且有效的证据。失败、未知、部分日志和旧版本结果不能因为存在一个文件就被跳过。修复off/on和不同质量配置分别统计，不汇成误导的单一成功率。

### 10.5 资源与故障证据的限度

重复创建/拒绝/销毁必须有真实活跃分配或等价对象/OS资源核对，以及阳性对照；heap计数占位返回0、进程exit0或RSS回落都不单独证明清理。

已见4292B/9块、8584B/18块平台增长不能未经归因写成cache。后续定义预热、测量次数、峰值/平台/趋势和具体资源容许条件，保留全部结果，不调预热来掩盖随循环增长。普通错误、合作取消、分配失败注入和进程终止分别建证据；没有可靠注入就列未覆盖。

进程内任意损坏图/崩溃恢复不属于已确认保证。声称隔离可用必须证明候选worker及父侧资源/提交协议，不能复用研究中的人工FailFast控制当生产验收。
