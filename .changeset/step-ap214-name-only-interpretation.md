Applications can explicitly select the pinned AP214 2010 compatibility subset
for one bare AUTOMOTIVE_DESIGN identifier. The source's edition stays unverified:
the original family name, empty OID and strict binding diagnostic remain owned.
Complete native results use AcceptedUnderInterpretation.

## Scope

[STEP semantics](../source/STEP_SEMANTICS/README.md), native import and the
independent benchmark probe. Type, unit, geometry and publication checks remain.

## Integrator action

Rebuild semantic/native libraries and consumers before using the new enum value.
Select Ap214NameOnlyAs2010, general geometry and nongeometric interoperability
explicitly; retain the owning assumption/report and separate interpreted results.

## Compatibility

Defaults and the existing eight-arc interpretation retain their exact identity
guards. The new --interpret-ap214-name-only-as-2010 option does not authenticate
an edition, add an OID or override another protocol or unknown identifier.
Conflicting CLI policies are rejected; registered identities gain no assumption.
Report policy names reflect the actual choice rather than a hardcoded old name.
