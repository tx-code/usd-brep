Native STEP import accepts an explicit source-hash-bound terminal NURBS domain
interpretation plan on the general development path. Source definitions and UV
remain immutable; complete new-domain defining geometry evidence shares the
selected quality budget. Completed results retain an owning interpretation
receipt and return `AcceptedUnderInterpretation`.

Unmarked nonclosed polynomial and positive-weight rational spline faces use
checked curve-intersection containment to retain outer/inner regions and source
shape roles. Native closed/pole charts and unknown source declarations still
refuse; source bounds are never rewritten. Reports identify the derived spline
region method and preserve the selected quality and publication gates.

Revolution faces use the existing bounded, tighter numerical projection recipe
with a separate same-parameter lift check. Single-period, pole-free revolution
regions can be classified without rewriting source outer-bound declarations.
Independent modeling copies containing STEP-parameterized composed edges forward
supported transforms through their owned support; borrowed bases are refused.

Complete derived-UV small-radius findings on eligible revolution faces can use
one independently selected binary U-chart conditioning trial. Full stored-net
identities, source-dependency alias rejection and explicit old-chart cache
invalidation preserve source definitions, generator STEP parameters and physical
budgets. Snapshot-owned chart correspondence survives report release; all native,
region, final-lift and final-identity checks still gate complete publication.

## Scope

[STEP import contract](../source/STEP_IMPORT/README.md).

## Integrator action

Rebuild matching SMLib, STEP_IMPORT and all native consumers together. Select the interpretation,
source identities, parameter ranges and resource limits explicitly when needed.

## Compatibility

Adds C++ option/report/snapshot APIs and opt-in STEP report fields. The default
source-domain policy and quality budgets are unchanged. Interpretation is distinct
from strict original import and is not transferred by native archive or modeling
copy; unvalidated combinations are rejected.
