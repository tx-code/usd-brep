The fixed AP214 assembly source checker retains direct bounded-wireframe product
definitions as `WireframeModel`, without inventing BRep shapes or placement-only
wrappers. Necessary source predicates, units and complete document ownership
remain mandatory. Native assembly import gives these definitions an independent
owning curve/point snapshot with zero BRep bodies. Parameter-preferred trimmed
splines retain their selected intervals, original cuts and direction, with one
whole-domain definition bound covering endpoint conversion and construction.
Queries and checked native archives retain the trim; cancellation and report
limits still gate the complete assembly. The current BRep-only scene exporter
explicitly refuses wire assemblies rather than dropping required geometry.
Native consumers must rebuild for the extended wire observation/assembly APIs.

Native STEP import accepts an explicit source-hash-bound terminal NURBS domain
interpretation plan on the general development path. Source definitions and UV
remain immutable; complete new-domain defining geometry evidence shares the
selected quality budget. Completed results retain an owning interpretation
receipt and return `AcceptedUnderInterpretation`.

Unmarked nonclosed polynomial and positive-weight rational spline faces use
checked curve-intersection containment to retain outer/inner regions and source
shape roles. Native closed/pole charts and unknown source declarations still
refuse; source bounds are never rewritten. Reports identify the derived spline
region method and preserve the selected quality and publication gates.

Revolution faces use the existing bounded, tighter numerical projection recipe
with a separate same-parameter lift check. Single-period revolution regions can
be classified without rewriting source outer-bound declarations. Native V-end
pole regions additionally require original vertex markers and exact stored-NURBS
evidence that every edge's pole-zone visits connect only to authorized endpoints.
Unsupported composed-curve proofs remain deferred; fitted caches, marker flags,
and a missing reported crossing are not substitutes for this evidence. Work is
request-cumulative and independently bounded; snapshots retain owning pole-visit
records. Native boundary-pole classification does not qualify source exact poles
or whole-surface regularity, and surface roles do not gain material semantics.

Source-pcurve-driven pole edges can now retain their actual UV/revolution
composition when both defining splines have finite positive-weight C0+ nets.
Outward interval value/derivative bounds cover generator-knot crossings and
stored-frame residuals without assuming an exactly axial pole center. Owning
receipts distinguish these regions from exact NURBS Bezier patches; both share
the existing request-wide work quota, cancellation and final publication gates.
Native carrier LEVEL2 remains mandatory, including the documented near-axis
representation limitation. Source priority, working zones and repair policy do
not change. Matching native consumers must rebuild for the additive receipt fields.
Independent modeling copies containing STEP-parameterized composed edges forward
supported transforms through their owned support; borrowed bases are refused.

Complete derived-UV small-radius findings on eligible revolution faces can use
one independently selected binary U-chart conditioning trial. Full stored-net
identities, source-dependency alias rejection and explicit old-chart cache
invalidation preserve source definitions, generator STEP parameters and physical
budgets. Snapshot-owned chart correspondence survives report release; all native,
region, final-lift and final-identity checks still gate complete publication.

Normally declared `CURVE_3D` surface curves retain their original 3D defining
geometry and parameter conversion. Every associated pcurve still undergoes
endpoint, direction and bidirectional image checks. Reverse trimmed curves
compose wrapper/basis and edge/loop senses explicitly. No source-priority
override or auxiliary-conflict exception is introduced by this declared path.
Reports distinguish the driving 3D curve from retained auxiliary parameters.

Applications can separately select original-hash-bound 3D priority for an exact
definition/shape/edge list. Original pcurve declarations and known comparison
refusals remain in the owning receipt; their original consistency is explicitly
unqualified. Actual target surfaces, topology, projection and working tolerances
keep their selected budgets. All plan entries and final native checks must finish
before complete publication as `AcceptedUnderInterpretation`; default source
priority and strict auxiliary checks remain unchanged.

The native import CLI transports that same explicit original/use-bound request,
including the original master and complete ordered pcurve list. Identity and use
budgets are required; malformed, mismatched and unused plans never publish.
Combined terminal-domain requests retain separate receipts. Conditional success
keeps exit code 11 and does not become ordinary source-priority acceptance.
The CLI's explicit assembly mode calls the same complete native assembly API
with separately declared usage, instance and depth limits. All roots and repeated
instances remain in the report; incompatible singular-query/archive modes refuse
before capture rather than flattening or dropping definitions.

The standalone viewer can transport the core's existing original-hash-bound
fixed AP214 schema interpretation for one explicit STEP file, including assembly
display. Scene adoption binds the requested/applied policy, immutable capture
identity and conditional qualification. Missing, mismatched, unused or strict
requests refuse without replacing the previous scene; scans cannot reuse a
single-original choice. No source, geometry or quality exception is added.

## Scope

[STEP import contract](../source/STEP_IMPORT/README.md).

## Integrator action

Rebuild matching SMLib, STEP_IMPORT and all native consumers together. Select the interpretation,
source identities, parameter ranges and resource limits explicitly when needed.

## Compatibility

Adds C++ option/report/snapshot APIs and opt-in STEP report fields. The default
source-domain policy and quality budgets are unchanged. Interpretation is distinct
from strict original import and is not transferred by native archive or modeling
copy; unvalidated combinations are rejected.
