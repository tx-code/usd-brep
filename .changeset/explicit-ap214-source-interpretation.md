Native STEP import provides an explicitly selected fixed AP214 interpretation for
one unregistered eight-arc identifier. It retains the original HEADER identity and
binding diagnostic, runs the complete selected source/native checks, and returns
`AcceptedUnderInterpretation` separately from ordinary acceptance. Owning semantic
snapshots and face views retain the interpretation assumption.

## Scope

[Native STEP import](../source/STEP_IMPORT/README.md).

## Integrator action

Rebuild C++ consumers with matching C++20 SDK headers/libraries. Opt in only with
general development quality and nongeometric interoperability; handle the distinct
result explicitly and keep it separate from ordinary source-qualified acceptance.
The native CLI returns 11 when it delivers an interpreted model; ordinary success
remains 0. Keep the original report when exporting an unqualified native archive.

## Compatibility

The C++ options/semantic result layouts and status enum gain fields/values; all
consumers must be rebuilt. Existing requests, registry identities, catalogs,
default reports, geometry/quality policy, ownership and atomic publication remain
unchanged. The new mode does not authenticate the disputed schema identity or
grant full AP conformance, continuous error bounds or production accuracy.
